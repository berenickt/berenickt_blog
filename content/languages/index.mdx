## 1. 프로그래밍 언어의 유형 분류

### 1.1 추상화 수준에 따른 분류

- `저급 언어(Low-Level Language)`
  - 컴퓨터가 직접 이해할 수 있거나(기계어), 그에 가까운 언어(어셈블리어)
  - 실행 속도는 빠르지만, CPU마다 기계어가 달라 **호환성이 없고**, 읽고 유지보수하기 어렵다.
- `고급 언어(High-Level Language)`
  - 사람이 이해하기 쉬운 문법으로 작성하는 언어 (C, Java, Python 등)
  - 실행하려면 기계어로 **번역하는 과정** (컴파일 또는 인터프리트)이 필요하다.

```
고급 언어      :  int sum = a + b;
     ↓ 컴파일
어셈블리어     :  mov eax, [a]
                 add eax, [b]
     ↓ 어셈블
기계어         :  10001011 01000101 ...
```

> 💡 C는 고급 언어지만 메모리를 직접 다룰 수 있어서, "고급 언어 중 가장 저급 언어에 가까운 언어"라고도 한다.

---

### 1.2 프로그래밍 패러다임에 따른 분류

**패러다임** 은 "프로그램을 어떤 관점으로 바라보고 작성하는가"에 대한 스타일이다.

| 패러다임         | 핵심 아이디어                                                     | 대표 언어                          |
| ---------------- | ----------------------------------------------------------------- | ---------------------------------- |
| **명령형**       | 컴퓨터가 수행할 **절차(어떻게)** 를 순서대로 기술하고 상태를 바꿈 | C, FORTRAN, (대부분의 언어)        |
| ├ 절차적         | 명령형 + 코드를 **함수(프로시저)** 단위로 나눔                    | C, COBOL, Pascal                   |
| └ 객체지향       | 명령형 + 데이터와 기능을 **객체** 로 묶고, 객체끼리 메시지를 주고받음 | Java, C++, C#, Python           |
| **선언형**       | **무엇을** 원하는지만 기술하고, 어떻게 할지는 시스템에 맡김       | SQL, HTML, Prolog                  |
| ├ 함수형         | 계산을 **수학적 함수의 조합** 으로 보고, 상태 변경과 부수 효과를 피함 | Haskell, Lisp, Scala, Elixir     |
| └ 논리형         | 사실과 규칙(논리 문장)을 선언하면, 조건을 만족하는 답을 추론      | Prolog                             |

```js
// 명령형 : "어떻게" — 반복문으로 하나씩 처리하며 상태(result)를 바꿈
const result = []
for (let i = 0; i < nums.length; i++) {
  if (nums[i] % 2 === 0) result.push(nums[i] * 2)
}

// 선언형(함수형 스타일) : "무엇을" — 짝수만 골라 2배 한 것
const result2 = nums.filter(n => n % 2 === 0).map(n => n * 2)
```

> 💡 JavaScript, Python, Kotlin, Swift, Rust 같은 현대 언어는 **명령형·객체지향·함수형을 모두 지원** 한다. 패러다임은 "언어의 종류"라기보다 **"코드를 짜는 스타일"** 로 이해하면 좋다.

### 1.3 실행(번역) 방식에 따른 분류

| 방식                      | 동작                                                                       | 장점                         | 단점                          | 예시                    |
| ------------------------- | -------------------------------------------------------------------------- | ---------------------------- | ----------------------------- | ----------------------- |
| **컴파일 언어**           | 실행 전에 소스 코드 **전체를 기계어로 번역** (실행 파일 생성)              | 실행 속도가 빠름             | 번역(빌드) 시간, 플랫폼마다 빌드 | C, C++, Go, Rust, Swift |
| **인터프리터 언어**       | 실행하면서 소스 코드를 **조금씩 번역해서 바로 실행**                       | 빌드 없이 바로 실행, 수정이 빠름 | 실행 속도가 상대적으로 느림 | Python, Ruby, PHP       |
| **바이트코드 언어**       | 먼저 **중간 코드(바이트코드)** 로 컴파일하고, **가상 머신(VM)** 이 실행     | 한 번 빌드로 여러 OS에서 실행 | VM이 필요                     | Java, Kotlin, C#        |

- 컴파일은 **번역** (책 한 권을 미리 통째로 번역), 인터프리트는 **통역** (말하는 대로 바로바로 옮김)에 비유한다.
- 실제로는 경계가 흐려졌다.
  - **JIT(Just-In-Time) 컴파일** : 실행 중에 자주 쓰이는 코드를 기계어로 컴파일해서 빠르게 실행한다. Java의 JVM, JavaScript의 V8 엔진이 대표적이다. 그래서 JavaScript는 "인터프리터 언어"로 분류되지만 생각보다 빠르다.
  - Python도 실제로는 소스를 **바이트코드(.pyc)로 컴파일한 뒤** 가상 머신이 실행한다.
  - **트랜스파일(transpile)** : 한 언어를 다른 언어로 변환하는 것. TypeScript → JavaScript, 최신 JS → 구형 JS(Babel) 등
  - **WebAssembly** : C++, Rust, Go 등을 브라우저에서 빠르게 실행할 수 있게 하는 바이너리 형식

### 1.4 타입 시스템에 따른 분류

| 구분            | 의미                                                                 | 예시                                      |
| --------------- | -------------------------------------------------------------------- | ----------------------------------------- |
| **정적 타입**   | 변수의 타입이 **컴파일할 때** 정해지고 검사된다                      | C, Java, Go, Rust, TypeScript, Kotlin     |
| **동적 타입**   | 변수의 타입이 **실행할 때** 정해진다. 같은 변수에 다른 타입 값도 가능 | Python, JavaScript, Ruby, PHP            |
| **강한 타입**   | 타입이 다른 값끼리 섞을 때 **자동 변환을 거의 하지 않는다**          | Python(`"1" + 1` → 오류), Java           |
| **약한 타입**   | 다른 타입끼리 **자동으로 변환(암묵적 형변환)** 하는 경우가 많다      | JavaScript(`"1" + 1` → `"11"`), C        |

- 정적 타입 : 오류를 **실행 전에** 잡고, 에디터 자동 완성이 강력하다. → 대규모 프로젝트에 유리
- 동적 타입 : 코드가 짧고 빠르게 작성할 수 있다. → 작은 스크립트, 프로토타입에 유리
- 그래서 동적 타입 언어도 **타입을 보완하는 방향** 으로 발전했다. (JavaScript → TypeScript, Python → 타입 힌트 + mypy·pyright)

### 1.5 메모리 관리 방식에 따른 분류

| 방식                         | 설명                                                                | 예시                     |
| ---------------------------- | ------------------------------------------------------------------- | ------------------------ |
| **수동 관리**                | 개발자가 직접 메모리를 할당하고 해제한다. 빠르지만 실수하면 메모리 누수·보안 취약점 | C, C++               |
| **가비지 컬렉션(GC)**        | 쓰지 않는 메모리를 런타임이 **자동으로 정리** 한다. 편하지만 정리하는 순간 잠깐 멈출 수 있다 | Java, Python, JS, Go, C# |
| **참조 카운팅(ARC)**         | 객체를 가리키는 참조 수를 세어 0이 되면 해제                         | Swift, Objective-C, (Python 일부) |
| **소유권(Ownership)**        | 컴파일러가 **컴파일 시점에** 메모리 해제 시점을 결정. GC 없이 안전하고 빠름 | Rust                |

> 💡 메모리 관리 실수로 생기는 보안 취약점이 많아서, 최근에는 C·C++ 대신 Rust 같은 **메모리 안전 언어** 를 쓰자는 움직임이 커지고 있다. (리눅스 커널, 안드로이드, 윈도우 일부에 Rust 도입)

## 2. 절차적 프로그래밍 언어

### 2.1 개념

- 일련의 처리 절차를 정해진 문법에 따라 **순서대로** 기술하는 언어
- 프로그램을 **프로시저(루틴, 서브루틴, 함수)** 단위로 나눠 작성한다.
- 데이터와 그 데이터를 처리하는 함수가 **분리** 되어 있다.

### 2.2 장단점

- 장점
  - 함수로 코드를 재사용할 수 있다.
  - 컴퓨터의 처리 구조와 비슷해 실행 속도가 빠르다.
  - 구조가 단순해 작은 프로그램은 이해하기 쉽다.
- 단점
  - 프로그램이 커지면 함수와 데이터의 관계를 파악하기 어렵다.
  - 데이터 구조가 바뀌면 그 데이터를 쓰는 모든 함수를 고쳐야 해서 유지보수가 어렵다.

### 2.3 종류

- `C`
  - 1972년 데니스 리치가 **유닉스 운영체제를 작성하기 위해** 개발한 시스템 프로그래밍 언어
  - 이식성이 뛰어나고, 지금도 운영체제·임베디드·다른 언어의 구현(Python 인터프리터 등)에 쓰인다.
- `COBOL`
  - 금융, 인사 같은 **비즈니스 데이터 처리** 를 위해 설계된 언어 (1959년)
  - 4개의 DIVISION으로 구성. 지금도 은행·보험사의 오래된 시스템에 남아 있다.
- `FORTRAN` : 최초의 고급 언어 중 하나(1957년). **과학·공학 계산** 용
- `BASIC` : **교육용** 으로 개발되어 문법이 쉽다.
- `Pascal` : 구조적 프로그래밍 교육용으로 널리 쓰였다.

## 3. 객체지향 프로그래밍 언어

### 3.1 개념

- 프로그램을 **객체(데이터 + 그 데이터를 다루는 기능)** 의 모음으로 보고, 객체끼리 **메시지(메서드 호출)를 주고받으며** 동작하게 만드는 방식
- 현실 세계의 사물(사용자, 주문, 상품)을 그대로 객체로 모델링할 수 있다.

```java
class Dog extends Animal {          // 상속
  private String name;              // 캡슐화 + 정보 은닉

  @Override
  public String sound() {           // 다형성 (오버라이딩)
    return "멍멍";
  }
}
```

### 3.2 특징

- `캡슐화(Encapsulation)`
  - 데이터와 연산(메서드)을 하나로 묶어 캡슐처럼 만드는 것
  - 내부 구현이 외부에 숨겨져서, 내부를 바꿔도 다른 코드에 미치는 영향이 적다. 재사용이 쉽다.
- `정보 은닉(Information Hiding)`
  - 객체의 내부 데이터를 숨기고, **공개된 메서드를 통해서만** 접근하게 하는 것 (`private`, `public` 같은 접근 제어자)
- `상속(Inheritance)`
  - 상위 클래스의 데이터와 연산을 하위 클래스가 물려받는 것
  - 접근 제어자에 따라 물려받는 범위가 달라진다. (Java에서는 `private` 멤버는 하위 클래스에서 직접 접근 불가)
  - Java·TypeScript 등에서는 `extends` 키워드를 쓴다.
- `다형성(Polymorphism)`
  - 같은 이름의 메서드 호출이 **객체에 따라 다르게 동작** 하는 것
  - `오버로딩` : 같은 이름, 다른 매개변수의 메서드를 여러 개 정의
  - `오버라이딩` : 상위 클래스의 메서드를 하위 클래스에서 재정의
- `추상화(Abstraction)`
  - 불필요한 부분을 생략하고, 객체의 **핵심적인 특징만** 뽑아 표현하는 것 (추상 클래스, 인터페이스)

### 3.3 장단점

- 장점
  - 재사용성, 생산성 향상
  - 현실 세계를 자연스럽게 모델링
  - 유지보수가 쉽다. (변경이 한 객체 안에 머무름)
- 단점
  - 설계에 시간이 들고, 처음 개발 속도가 느려질 수 있다.
  - 상속을 남용하면 클래스 구조가 복잡해진다. → 요즘은 **"상속보다 조합(composition)"** 을 권장한다.
  - 예전에는 실행 속도가 느리다는 단점이 있었지만, 지금은 컴파일러·런타임 최적화로 대부분 큰 차이가 없다.

### 3.4 종류

- `Simula 67` : **최초의 객체지향 언어** (1967년)
- `Smalltalk` : 순수 객체지향 언어. **GUI 개발 환경** 을 함께 선보이며 이후 GUI와 객체지향에 큰 영향을 줌
- `C++` : C에 객체지향을 더한 언어
- `Java` : 객체지향 언어의 대표. "한 번 작성하면 어디서나 실행(Write Once, Run Anywhere)"
- `C#` : 마이크로소프트의 Java와 비슷한 객체지향 언어
- `Objective-C` : 예전 애플(iOS·macOS) 개발의 주력 언어. 지금은 **Swift** 로 대부분 대체
- `Python`, `Ruby`, `Kotlin`, `Swift` : 객체지향을 지원하는 현대 언어들

cf. 객체지향 설계는 [디자인 패턴 - OOP](/cs/design-pattern/01-OOP) 참고

## 4. 스크립트 언어

### 4.1 개념

- 원래는 **다른 프로그램(응용 소프트웨어)을 제어하거나 자동화** 하기 위해 그 안에 삽입되어 동작하는 언어를 말했다.
  - e.g. 브라우저 안의 JavaScript, 게임 안의 Lua, 엑셀 안의 VBA
- 보통 **별도의 컴파일 과정 없이 바로 실행** 되고, 문법이 간결하다.
- 지금은 JavaScript(Node.js), Python처럼 **대규모 애플리케이션 개발에도 쓰이면서** "스크립트 언어"와 "일반 언어"의 경계가 거의 사라졌다.

### 4.2 종류

- `JavaScript`
  - HTML 문서에 삽입되어 웹 페이지를 **동적이고 인터랙티브하게** 만든다.
  - Node.js 덕분에 서버·도구 개발에도 쓰이며, 지금은 가장 널리 쓰이는 언어 중 하나다.
- `Python`
  - 네덜란드의 귀도 반 로섬(Guido van Rossum)이 개발한 객체지향 스크립트 언어
  - 문법이 쉽고 읽기 좋아 교육, 자동화, 데이터 분석, **AI** 분야의 표준 언어가 되었다.
  - 별도 빌드 없이 실행하며, 운영체제에 독립적이다.
- `PHP`
  - HTML 안에 포함해 작동하는 **서버 측** 스크립트 언어
  - 전통적으로 Linux + Apache + MySQL + PHP(**LAMP**) 조합으로 많이 쓰였고, 지금도 워드프레스 등 많은 웹사이트를 움직인다.
- `Ruby` : 개발자의 즐거움을 강조한 언어. 웹 프레임워크 Ruby on Rails로 유명
- `Perl` : 유닉스 계열에서 텍스트 처리·시스템 관리에 많이 쓰인 언어
- `Shell Script (Bash)` : 리눅스·유닉스 명령어 자동화
- `Lua` : 게임(로블록스 등)에 삽입되는 가벼운 스크립트 언어
- 옛날 웹 기술
  - `JSP` : HTML 안에 Java 코드를 넣어 서버에서 페이지를 만드는 기술. 지금은 Thymeleaf나 프론트엔드 분리 방식으로 대부분 대체
  - `ASP` : 마이크로소프트 윈도우 서버의 웹 스크립트 기술. 지금은 **ASP.NET** 으로 대체
  - `VBScript` : Visual Basic 기반 스크립트. 마이크로소프트가 지원 종료 중

## 5. 선언형 언어

### 5.1 개념

- 프로그램이 **"무엇을" 해야 하는지(목표)** 를 기술하고, **"어떻게" 할지(알고리즘)는 명시하지 않는** 언어
- 실행 방법은 언어의 엔진(DB, 브라우저 등)이 알아서 정한다.
- 가독성이 좋고, 오류가 적다.

```sql
-- "서울에 사는 사용자의 이름을 줘" 라고만 선언 (어떤 순서로 찾을지는 DB가 결정)
SELECT name FROM users WHERE city = '서울';
```

```html
<!-- "여기에 제목과 버튼이 있다" 라고만 선언 (어떻게 그릴지는 브라우저가 결정) -->
<h1>안녕하세요</h1>
<button>시작하기</button>
```

### 5.2 종류

- `SQL` : 데이터베이스의 데이터를 조회·관리하기 위한 언어
- `HTML` : 웹 콘텐츠의 의미와 구조를 정의하는 **마크업 언어** (엄밀히는 프로그래밍 언어가 아니다)
- `CSS` : 웹 콘텐츠의 모양을 선언하는 스타일 언어
- `Haskell` : 순수 함수형 프로그래밍 언어
- `Prolog` : 논리형 언어
- 그 밖에 : 정규 표현식, YAML·JSON 설정 파일, Terraform(HCL) 같은 인프라 코드도 선언형 방식이다.

> 💡 React(`UI = f(state)`), SwiftUI, Jetpack Compose, Flutter처럼 **"상태가 이렇다면 화면은 이렇다"** 라고 선언하는 **선언형 UI** 가 지금의 주류다.

## 6. 언어별 특징 정리

### 6.1 C / C++

- **C** : 하드웨어를 직접 다루는 시스템 언어. 포인터와 메모리를 직접 관리한다. 운영체제·임베디드의 기본
- **C++** : C의 성능 + 객체지향·템플릿·STL. **게임 엔진(Unreal), 브라우저, 고성능 금융 시스템** 등 속도가 중요한 곳
- 단점 : 메모리 관리를 잘못하면 버그와 보안 취약점이 생기기 쉽다. 학습 난이도가 높다.

### 6.2 Java / Kotlin

- **Java** : JVM 위에서 실행되어 OS에 상관없이 동작. 강력한 생태계(Spring)와 안정성 덕분에 **국내 기업 백엔드의 표준**
  - 최근 버전은 레코드(record), 가상 스레드 등으로 계속 현대화되고 있다.
- **Kotlin** : Java와 100% 호환되면서 **더 간결하고 null 안전성** 을 갖춘 언어. **안드로이드 공식 언어** 이며, 백엔드(Spring)에서도 빠르게 늘고 있다.

### 6.3 C#

- 마이크로소프트의 .NET 플랫폼 언어. Java와 비슷하지만 언어 기능이 풍부하다.
- **Unity 게임 개발**, 윈도우 앱, 기업용 백엔드(ASP.NET Core)

### 6.4 Python

- 쉬운 문법과 방대한 라이브러리. "배터리 포함(batteries included)" 철학
- **AI·머신러닝(PyTorch), 데이터 분석(pandas), 자동화, 백엔드(FastAPI, Django)**
- 단점 : 순수 연산 속도는 느린 편 (무거운 계산은 C로 만든 라이브러리가 처리)

### 6.5 JavaScript / TypeScript

- **JavaScript** : 브라우저에서 실행되는 **유일한 언어**(+ WebAssembly). Node.js로 서버까지. 웹 개발의 필수
- **TypeScript** : JavaScript에 **정적 타입** 을 더한 언어. 대규모 웹 프로젝트의 사실상 표준이 되었다.
  - 컴파일러가 Go로 다시 작성된 TypeScript 7(2026)부터 타입 검사가 크게 빨라졌다.

cf. [JavaScript](/languages/js/01-Introduce), [TypeScript](/languages/ts/01-introduce)

### 6.6 Go

- 구글이 만든 **단순하고 빠른** 언어. 문법이 작아 배우기 쉽다.
- **goroutine** 으로 동시성 프로그래밍이 쉽고, 실행 파일 하나로 배포된다.
- Docker, Kubernetes, Terraform 등 **클라우드·인프라 도구** 의 언어

### 6.7 Rust

- **GC 없이 메모리 안전성을 보장** 하는 언어(소유권·빌림 개념). C++ 수준의 성능
- 시스템 프로그래밍, 고성능 도구(Vite의 Rolldown, Biome, Turbopack 등 웹 도구도 Rust로), WebAssembly
- 단점 : 소유권 개념 때문에 학습 곡선이 가파르다.

### 6.8 Swift / Dart

- **Swift** : 애플이 Objective-C를 대체하려고 만든 언어. iOS·macOS 앱 개발의 표준
- **Dart** : 구글이 만든 언어. **Flutter** 로 모바일·웹·데스크톱 앱을 만들 때 쓴다.

cf. [Dart](/languages/dart/01-basic), [모바일·데스크톱 앱 개발 방식 비교](/mobile)

## 7. 어떤 언어를 배워야 할까?

| 하고 싶은 분야            | 추천 언어                                     |
| ------------------------- | --------------------------------------------- |
| 웹 프론트엔드             | **JavaScript → TypeScript** (필수)            |
| 웹 백엔드                 | Java/Kotlin(Spring), TypeScript(Node.js), Python, Go |
| 안드로이드 / iOS          | Kotlin / Swift (크로스 플랫폼은 TypeScript·Dart) |
| AI·데이터                 | **Python** (+ SQL)                            |
| 게임                      | C#(Unity), C++(Unreal)                        |
| 시스템·임베디드           | C, C++, Rust                                  |
| 클라우드·인프라·DevOps    | Go, Python, Shell                             |
| CS 기초 공부              | C (메모리·포인터 이해), Python (알고리즘)     |

- 처음에는 **하나를 깊게** 배우자. 변수, 조건문, 반복문, 함수, 자료구조, 객체 같은 개념은 모든 언어에 공통이라, 두 번째 언어부터는 훨씬 빨리 배운다.
- 언어보다 중요한 것은 **CS 기초와 문제 해결 능력** 이다. → [컴퓨터과학 로드맵](/cs)
