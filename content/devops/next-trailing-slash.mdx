## 1. Trailing Slash란?

**트레일링 슬래시(Trailing Slash)** 는 URL 끝에 붙은 슬래시 `/` 를 말한다.

```
https://example.com/about    ← 트레일링 슬래시 없음
https://example.com/about/   ← 트레일링 슬래시 있음
```

- 사람 눈에는 같아 보이지만, **웹에서는 서로 다른 URL** 이다.
- 관례적으로 끝에 `/`가 있으면 **디렉터리(폴더)**, 없으면 **파일** 처럼 다룬다.
  - 전통적인 웹 서버는 `/about/` 요청을 받으면 `about/` 폴더 안의 `index.html`을 응답한다.
- 단, 도메인 바로 뒤의 슬래시(`https://example.com` ↔ `https://example.com/`)는 브라우저가 항상 `/`로 맞춰 주므로 같은 주소다. 차이가 생기는 건 **경로(path) 뒤** 의 슬래시다.

---

### 1.1 왜 신경 써야 할까?

**1. 정적 호스팅에서 파일을 못 찾는 문제 (가장 중요)**

서버 없이 파일만 올려 두는 정적 호스팅(S3 등)은 **URL과 파일 이름이 정확히 맞아야** 응답한다. (2장)

**2. 상대 경로가 다르게 해석된다**

같은 HTML에 `<img src="logo.png">`가 있을 때

| 현재 URL       | `logo.png`가 가리키는 주소 |
| -------------- | -------------------------- |
| `/blog/post`   | `/blog/logo.png`           |
| `/blog/post/`  | `/blog/post/logo.png`      |

→ 슬래시 하나로 이미지·스크립트 경로가 깨질 수 있다. (그래서 정적 파일은 `/`로 시작하는 절대 경로를 쓰는 게 안전하다)

**3. SEO : 같은 내용, 두 개의 주소**

- `/about`과 `/about/`이 둘 다 같은 내용으로 응답하면, 검색 엔진은 **중복 콘텐츠** 로 볼 수 있다.
- 그래서 **한 가지 형태로 정하고, 다른 형태는 그쪽으로 리다이렉트** 하는 것이 정석이다. (`<link rel="canonical">`도 함께 지정)

## 2. Next.js의 `trailingSlash` 옵션

```js
// next.config.js
/** @type {import('next').NextConfig} */
const nextConfig = {
  trailingSlash: true, // 기본값 false
}

module.exports = nextConfig
```

이 옵션 하나가 **URL 형태** 와 **정적 빌드 결과 파일 구조** 를 함께 바꾼다.

| 구분                         | `trailingSlash: false` (기본)          | `trailingSlash: true`                  |
| ---------------------------- | -------------------------------------- | -------------------------------------- |
| 대표 URL                     | `/about`                               | `/about/`                              |
| 반대 형태로 접속하면         | `/about/` → `/about` 로 **308 리다이렉트** | `/about` → `/about/` 로 **308 리다이렉트** |
| 정적 빌드(`output: 'export'`) 결과 | `out/about.html`                  | `out/about/index.html`                 |
| `next/link`가 만드는 주소    | `/about`                               | `/about/`                              |

- 리다이렉트는 **Next.js 서버가 실행 중일 때**(`next start`, Vercel 등) 동작한다.
- 정적 빌드로 파일만 올리면 Next.js 서버가 없으므로, 리다이렉트와 파일 찾기는 **호스팅 서비스의 몫** 이 된다. 그래서 정적 배포에서 이 옵션이 중요해진다.
- 리다이렉트 없이 두 형태를 모두 직접 처리하고 싶다면 `skipTrailingSlashRedirect: true` 옵션으로 자동 리다이렉트를 끌 수 있다. (미들웨어에서 직접 처리할 때)

## 3. 정적 빌드(SSG)와 trailingSlash

### 3.1 정적 빌드하기

```js
// next.config.js
const nextConfig = {
  output: 'export', // next build 시 out/ 폴더에 정적 파일 생성
  trailingSlash: true,
  images: { unoptimized: true }, // 정적 export에서는 이미지 최적화 서버를 쓸 수 없음
}
```

```bash
npm run build   # → out/ 폴더 생성
```

> 💡 예전에는 `"build:ssg": "next build && next export"` 처럼 **`next export` 명령어** 로 정적 빌드를 했다.
> 이 명령은 Next.js 14에서 제거되었고, 지금은 `output: 'export'` 설정 후 `next build`만 하면 된다.
> 같은 프로젝트를 SSR로도 빌드하려면 환경 변수로 `output` 값을 바꾸는 식으로 나눈다.

### 3.2 빌드 결과 비교

`app/boards/page.tsx` (또는 `pages/boards/index.tsx`) 페이지가 있을 때

```
trailingSlash: false            trailingSlash: true
out/                            out/
├── index.html                  ├── index.html
├── 404.html                    ├── 404.html
└── boards.html                 └── boards/
                                    └── index.html
```

### 3.3 왜 S3에서는 `true`가 필요할까?

사용자가 `https://example.com/boards`로 접속했을 때

- **`false` (`boards.html`)** : S3는 `boards`라는 이름의 파일을 찾는다. 실제 파일은 `boards.html`이라 **404** 가 난다.
- **`true` (`boards/index.html`)** : S3 정적 웹사이트 호스팅은 폴더 요청에 인덱스 문서(`index.html`)를 응답하고, `/boards`처럼 슬래시 없이 와도 `/boards/`로 리다이렉트해 준다. → **정상 동작**

즉, `trailingSlash: true`는 **"폴더 + index.html" 구조를 이해하는 전통적인 정적 서버** 와 궁합이 맞다.

## 4. 호스팅 환경별 정리

| 호스팅 환경                                 | trailingSlash 필요?        | 이유                                                                   |
| ------------------------------------------- | -------------------------- | ---------------------------------------------------------------------- |
| Vercel, Netlify, Cloudflare Pages           | 대부분 불필요              | `about.html`을 `/about`으로 알아서 연결하는 **Clean URL** 기능 내장    |
| **S3 정적 웹사이트 호스팅**                 | **`true` 권장**            | 폴더의 `index.html`은 찾지만, 확장자 없는 경로를 `.html`로 연결하지 않음 |
| **S3(비공개) + CloudFront(OAC)** ✅ 운영 권장 | `true` + **CloudFront Function** | REST 엔드포인트는 하위 폴더의 `index.html`도 자동으로 찾지 않음   |
| Nginx                                       | 설정으로 해결 가능         | `try_files`로 원하는 파일을 찾도록 지정                                |
| GitHub Pages                                | `true` 권장                | 폴더의 `index.html`을 자동으로 응답                                    |
| Next.js 서버 (`next start`, Docker)         | 선택                       | Next.js가 직접 라우팅·리다이렉트 처리                                  |

### 4.1 CloudFront Function으로 index.html 붙이기

비공개 S3 버킷을 CloudFront(OAC)로 서비스할 때는, CloudFront 앞단에서 요청 경로를 고쳐 준다.

```js
// CloudFront Functions (뷰어 요청 이벤트에 연결)
function handler(event) {
  var request = event.request
  var uri = request.uri

  if (uri.endsWith('/')) {
    // /boards/ → /boards/index.html
    request.uri += 'index.html'
  } else if (!uri.includes('.')) {
    // /boards → /boards/index.html (확장자가 없는 경로)
    request.uri += '/index.html'
  }
  return request
}
```

- `trailingSlash: false`로 빌드했다면 `request.uri += '.html'`로 바꾸면 된다.
- 전체 배포 과정은 [AWS 서비스와 배포 전략 - 실습](/devops/aws-services-deploy) 참고

### 4.2 Nginx 예시

```nginx
location / {
  # /boards → boards → boards.html → boards/index.html 순서로 찾기
  try_files $uri $uri.html $uri/index.html /404.html;
}
```

## 5. 정리

- 트레일링 슬래시가 있는 URL과 없는 URL은 **서로 다른 주소** 다. 하나로 정하고, 나머지는 리다이렉트하자.
- Next.js의 `trailingSlash`는 **URL 형태** 와 **정적 빌드 파일 구조**(`about.html` vs `about/index.html`)를 함께 결정한다.
- **S3 같은 정적 호스팅** 에 올린다면 `trailingSlash: true`가 가장 간단한 해결책이다.
- Vercel·Netlify 같은 플랫폼이나 Next.js 서버로 배포한다면 크게 신경 쓰지 않아도 된다. 이미 운영 중인 사이트라면 **URL 형태를 바꿀 때 기존 주소가 리다이렉트되는지** 꼭 확인하자.
