## 1. Kubernetes란?

- 여러 서버에 걸쳐 컨테이너를 배포·확장·관리해주는 **컨테이너 오케스트레이션** 도구
  - 오케스트레이션이 왜 필요한지는 [Docker - Orchestration](/devops/docker/10-orchestration) 참고
- 줄여서 `K8s` (K와 s 사이 글자가 8개)
- Google 내부 시스템 Borg의 경험을 바탕으로 만들어져, 2014년 오픈소스로 공개
  - 현재는 CNCF(Cloud Native Computing Foundation)에서 관리

---

## 2. 왜 쓸까?

- `자동 복구(Self-healing)`: 컨테이너가 죽으면 자동으로 다시 실행
- `스케일링`: 트래픽에 따라 컨테이너 수를 늘리고 줄임
- `무중단 배포`: 새 버전으로 하나씩 교체(Rolling Update), 문제가 생기면 롤백
- `서비스 디스커버리·로드밸런싱`: 컨테이너 IP가 바뀌어도 이름으로 접근, 트래픽 자동 분산
- `선언형 관리`: "이 앱을 3개 띄워둬"라고 YAML로 원하는 상태를 적으면, K8s가 계속 그 상태를 유지

---

## 3. 구조

- `Cluster`: K8s 전체 (Control Plane + Node들)
- `Control Plane`: 클러스터를 관리하는 두뇌
  - `kube-apiserver`: 모든 요청을 받는 입구 (`kubectl`도 여기로 요청)
  - `etcd`: 클러스터 상태를 저장하는 Key-Value 저장소
  - `kube-scheduler`: 새 Pod를 어느 Node에 둘지 결정
  - `kube-controller-manager`: 원하는 상태와 실제 상태를 비교해 맞춰줌
- `Node`: 실제로 컨테이너가 실행되는 서버
  - `kubelet`: Node에서 Pod를 실행·관리하는 에이전트
  - `kube-proxy`: 네트워크 규칙 관리
  - `Container Runtime`: 컨테이너를 실제로 실행 (containerd 등)

## 4. 주요 오브젝트

| 오브젝트     | 설명                                                          |
| ------------ | ------------------------------------------------------------- |
| `Pod`        | 가장 작은 배포 단위, 하나 이상의 컨테이너 묶음                |
| `ReplicaSet` | 같은 Pod를 지정한 개수만큼 유지                               |
| `Deployment` | ReplicaSet을 관리하며 롤링 업데이트·롤백 담당 (보통 이걸 사용) |
| `Service`    | Pod 묶음에 고정된 주소를 부여하고 트래픽을 분산               |
| `Ingress`    | 도메인·경로별로 외부 HTTP 요청을 Service로 연결               |
| `ConfigMap`  | 환경 설정 값                                                  |
| `Secret`     | 비밀번호·토큰 같은 민감한 값                                  |
| `Namespace`  | 클러스터 안을 논리적으로 나누는 공간 (dev, prod 등)           |

- Service 종류
  - `ClusterIP`(기본): 클러스터 내부에서만 접근
  - `NodePort`: 각 Node의 포트로 외부 접근
  - `LoadBalancer`: 클라우드 로드밸런서를 붙여 외부에 공개

## 5. YAML 예시

```yaml
# deployment.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-app
spec:
  replicas: 3                # Pod 3개 유지
  selector:
    matchLabels:
      app: my-app
  template:
    metadata:
      labels:
        app: my-app
    spec:
      containers:
        - name: my-app
          image: my-app:1.0.0
          ports:
            - containerPort: 3000
---
apiVersion: v1
kind: Service
metadata:
  name: my-app
spec:
  type: ClusterIP
  selector:
    app: my-app              # 이 라벨을 가진 Pod로 트래픽 전달
  ports:
    - port: 80
      targetPort: 3000
```

## 6. kubectl 자주 쓰는 명령어

```bash
kubectl apply -f deployment.yaml      # YAML대로 생성·수정
kubectl get pods                      # Pod 목록 (-o wide: 자세히)
kubectl get deploy,svc                # 여러 종류 한 번에 조회
kubectl describe pod <이름>           # 상세 정보·이벤트 (에러 원인 확인)
kubectl logs -f <pod이름>             # 로그 보기
kubectl exec -it <pod이름> -- sh      # 컨테이너 안으로 접속
kubectl scale deploy my-app --replicas=5
kubectl rollout undo deploy my-app    # 이전 버전으로 롤백
kubectl delete -f deployment.yaml
```

## 7. 로컬에서 연습하기

- `Docker Desktop`: 설정에서 Kubernetes 활성화
- `minikube`: 로컬에 단일 Node 클러스터 생성
- `kind`: Docker 컨테이너를 Node로 사용하는 가벼운 클러스터
- 운영 환경에서는 AWS EKS, GCP GKE 같은 관리형 서비스를 주로 사용
- 여러 YAML을 패키지로 묶어 관리하는 Helm은 [NestJS - Kubernetes & Helm](/backend/nestjs/50-kubernetes-helm) 참고
