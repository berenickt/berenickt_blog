## 1. 로컬 저장소와 원격 저장소

![git_6_1](https://raw.githubusercontent.com/berenickt/image-server/main/img/git_6_1.png)

Git이 **파일 버전을 저장해 두는 장소** 를 **저장소(repository)** 라고 한다.

| 구분            | 위치                                  | 예시                         |
| --------------- | ------------------------------------- | ---------------------------- |
| **로컬 저장소** | 내 컴퓨터의 작업 폴더 안 `.git` 폴더  | 지금까지 `git init`으로 만든 것 |
| **원격 저장소** | 인터넷 서버                           | GitHub, GitLab, Bitbucket    |

지금까지는 내 컴퓨터 안에서만 버전을 관리했다. 실제로 개발할 때는 로컬 저장소를 **원격 저장소에도 올려 두고** 함께 쓴다.

- **백업** : 컴퓨터가 고장 나거나 랜섬웨어에 걸려도 코드가 안전하다.
- **협업** : 다른 사람이 내 코드를 받아 가고, 각자 작업한 내용을 합칠 수 있다.
- **여러 컴퓨터에서 작업** : 회사 컴퓨터와 집 노트북에서 같은 프로젝트를 이어서 작업
- **공개·포트폴리오, 배포 자동화** : GitHub에 올린 코드로 Vercel·GitHub Actions 등이 자동 배포

```
내 컴퓨터 (로컬 저장소)  ──git push──▶  GitHub (원격 저장소)
                        ◀──git pull──
```

- `git push` : 로컬의 커밋을 원격 저장소로 **올린다.** (이 글)
- `git pull` / `git clone` : 원격 저장소의 커밋을 **내려받는다.** → [07-팀원과 함께 작업하기 : clone, pull, fetch](/devops/git/07-clone-pull)

## 2. GitHub에 원격 저장소 만들기

1. [github.com](https://github.com/)에 가입하고 로그인한다.
2. 오른쪽 위 **`+` → New repository** 를 누른다.
3. 저장소 이름을 정하고, **Public(공개) / Private(비공개)** 를 고른다.
4. **Create repository** 를 누른다.

> ⚠️ 이미 내 컴퓨터에 있는 프로젝트를 올릴 거라면, 저장소를 만들 때 **Add a README file, .gitignore, license 옵션은 체크하지 말고 빈 저장소** 로 만들자.
> 이 옵션을 체크하면 GitHub 쪽에 첫 커밋이 생겨서, 로컬 저장소와 이력이 달라지고 첫 push가 거부된다. (5.1 참고)

저장소를 만들면 GitHub가 연결 방법을 안내해 주는데, 그 명령어를 그대로 따라 해도 된다. 아래에서 하나씩 설명한다.

> 💡 GitHub CLI가 있다면 터미널에서 바로 만들고 연결할 수도 있다.
>
> ```bash
> gh repo create my-project --private --source=. --push
> ```

## 3. 로컬 저장소를 GitHub에 올리기

### 3.1 로컬 저장소 준비

```bash
mkdir my-project && cd my-project
git init                      # 로컬 저장소 만들기

git branch -M main            # 기본 브랜치 이름을 main으로 (이미 main이면 생략 가능)

echo "hello" > a.txt
git add .
git commit -m "a 파일 생성"    # 올릴 커밋이 최소 하나는 있어야 한다
```

- GitHub는 기본 브랜치 이름으로 `main`을 쓴다. 내 컴퓨터의 Git이 아직 `master`를 기본으로 쓴다면 `git branch -M main`으로 이름을 맞춘다.
- 앞으로 계속 `main`을 쓰려면 `git config --global init.defaultBranch main` → [01-설치](/devops/git/01-git-install)

### 3.2 원격 저장소 연결 : git remote add

원격 저장소 주소는 매번 입력하기에 너무 길다. 그래서 **이름(별명)을 붙여서 등록** 해 둔다.

```bash
# git remote add 이름 원격저장소주소
git remote add origin https://github.com/아이디/my-project.git

# 등록된 원격 저장소 확인
git remote -v
# origin  https://github.com/아이디/my-project.git (fetch)
# origin  https://github.com/아이디/my-project.git (push)
```

- **`origin`** 은 "기본 원격 저장소"에 관례적으로 붙이는 이름이다. 다른 이름을 써도 되지만 대부분 `origin`을 쓴다.
- 원격 저장소 주소는 GitHub 저장소 화면의 초록색 **Code** 버튼에서 복사할 수 있다.
  - **HTTPS** : `https://github.com/아이디/저장소.git`
  - **SSH** : `git@github.com:아이디/저장소.git` (SSH 키를 등록했다면 이쪽이 편하다)

### 3.3 올리기 : git push

```bash
# git push -u 원격이름 브랜치이름
git push -u origin main
```

- "로컬의 `main` 브랜치를 `origin`(GitHub)에 올려라"라는 뜻이다.
- 처음 push할 때 **GitHub 로그인(인증)** 을 요구할 수 있다.
  - GitHub는 계정 비밀번호로는 push할 수 없다. 브라우저 로그인 창이 뜨면 로그인하거나, `gh auth login` 또는 SSH 키로 미리 설정해 두자. → [01-설치 : GitHub 연결 준비](/devops/git/01-git-install)
- push가 끝나면 GitHub 저장소 페이지를 새로고침해 보자. 파일과 커밋 기록이 올라가 있다.

### 3.4 `-u` 옵션 : 다음부터는 `git push`만

`-u`(`--set-upstream`)는 **"내 로컬 `main` 브랜치는 `origin`의 `main` 브랜치와 짝이다"라고 연결(upstream 설정)** 해 두는 옵션이다.
한 번 설정해 두면 다음부터는 원격 이름과 브랜치 이름을 생략할 수 있다.

```bash
# a.txt 수정
git add .
git commit -m "a 파일 수정"
git push          # -u로 연결해 두었으므로 origin main으로 자동 push
```

- `git status`를 하면 `Your branch is ahead of 'origin/main' by 1 commit.`처럼 원격보다 몇 커밋 앞서 있는지도 알려 준다.
- 커밋 기록은 GitHub 저장소의 **Commits** 메뉴에서도 볼 수 있다.

## 4. 다른 브랜치 올리기

```bash
git switch -c feature/coupon
# 작업 후 커밋
git push -u origin feature/coupon     # 새 브랜치를 원격에 올리기 (처음 한 번 -u)
git push                              # 이후로는 이것만
```

- GitHub에 브랜치를 올리면 **Pull Request** 를 만들어 코드 리뷰를 받고 main에 합칠 수 있다. → [08-Pull Request로 협업하기](/devops/git/08-pull-request)
- 원격 브랜치 삭제 : `git push origin --delete feature/coupon`

## 5. push가 안 될 때

### 5.1 `rejected` : 원격에 내가 없는 커밋이 있을 때

```
! [rejected]        main -> main (fetch first)
error: failed to push some refs to 'https://github.com/아이디/my-project.git'
hint: Updates were rejected because the remote contains work that you do not have locally.
```

- 동료가 먼저 push했거나, GitHub에서 README를 만들었거나 해서 **원격 저장소에 내 로컬에 없는 커밋이 있으면** push가 거부된다.
- Git은 다른 사람의 작업을 덮어쓰지 않도록, **원격의 최신 내용을 먼저 받아서 합친 뒤에만** push를 허락한다.
- 해결 : `git pull`로 원격의 변경을 받아 합친 다음 다시 push → [07-팀원과 함께 작업하기 : clone, pull, fetch](/devops/git/07-clone-pull)

```bash
git pull origin main    # 원격 변경을 받아서 합치기 (충돌이 나면 해결 후 커밋)
git push
```

### 5.2 강제 push는 최후의 수단

```bash
git push --force              # ⚠️ 원격 이력을 내 로컬 이력으로 덮어씀
git push --force-with-lease   # 그나마 안전한 강제 push (그사이 다른 사람이 push했다면 거부)
```

- 강제 push는 **원격에 있던 다른 사람의 커밋을 지워 버릴 수 있다.** 함께 쓰는 브랜치(main 등)에는 절대 쓰지 말자.
- 혼자 쓰는 브랜치를 rebase·reset으로 정리한 뒤 다시 올릴 때만, `--force-with-lease`로 쓴다.
- 실수를 막기 위해 GitHub 저장소 설정에서 main 브랜치에 **보호 규칙(Branch protection rules)** 을 걸어 강제 push를 막을 수 있다.

### 5.3 인증 오류

- `Authentication failed`, `Permission denied` : 로그인 정보가 없거나 틀린 경우 → `gh auth login`으로 다시 로그인하거나 SSH 키 확인
- `Repository not found` : 저장소 주소가 틀렸거나, 비공개 저장소에 접근 권한이 없는 경우 → `git remote -v`로 주소 확인

## 6. 원격 저장소 관리 명령어

```bash
git remote -v                          # 등록된 원격 저장소 목록
git remote add 이름 주소                 # 원격 저장소 추가
git remote set-url origin 새주소         # 주소 변경 (e.g. HTTPS → SSH, 저장소 이름 변경 시)
git remote rename 옛이름 새이름          # 이름 변경
git remote remove 이름                   # 연결 끊기 (GitHub의 저장소가 지워지지는 않음)
git branch -vv                         # 로컬 브랜치마다 연결된 원격 브랜치(upstream) 확인
```

## 7. 올리지 말아야 할 파일 : .gitignore

원격 저장소에 올라간 파일은 **누구나 볼 수 있을 수도 있고, 한 번 올라가면 이력에 영원히 남는다.**
`.gitignore`에 적은 파일은 `git add .`를 해도 스테이징되지 않으므로, push하기 전에 꼭 설정하자.

- `node_modules/` : `package.json`만 있으면 `npm install`로 다시 만들 수 있으므로 올리지 않는다.
- 빌드 결과물 (`dist/`, `.next/` 등)
- **`.env` 같은 비밀 키 파일** ⚠️ : 공개 저장소에 올라간 키는 몇 분 안에 자동 수집되어 악용될 수 있다.

작성 방법은 [02-버전 기록과 비교 : .gitignore](/devops/git/02-add-commit-diff) 참고

## 8. 정리

| 하고 싶은 것                         | 명령어                                      |
| ------------------------------------ | ------------------------------------------- |
| 원격 저장소 등록                     | `git remote add origin 주소`                |
| 등록된 원격 저장소 확인              | `git remote -v`                             |
| 처음 push (upstream 연결)            | `git push -u origin main`                   |
| 이후 push                            | `git push`                                  |
| 새 브랜치 올리기                     | `git push -u origin 브랜치이름`             |
| push가 거부될 때                     | `git pull` 후 다시 `git push`               |
| 원격 주소 바꾸기                     | `git remote set-url origin 새주소`          |
| 원격 브랜치 삭제                     | `git push origin --delete 브랜치이름`       |

다음 글에서는 원격 저장소를 내려받고(clone), 동료가 올린 최신 코드를 받아오는(pull) 방법을 배운다. → [07-팀원과 함께 작업하기 : clone, pull, fetch](/devops/git/07-clone-pull)
