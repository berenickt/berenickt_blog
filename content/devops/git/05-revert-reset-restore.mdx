## 1. 한눈에 보기

Git은 버전 관리 프로그램이라, 언제든 **이전 상태로 돌아가거나, 문제가 된 커밋을 취소** 할 수 있다.
되돌리는 대상에 따라 쓰는 명령어가 다르다.

| 명령어          | 되돌리는 대상                       | 비유                         | 이력(커밋)              | 협업 중 사용 |
| --------------- | ----------------------------------- | ---------------------------- | ----------------------- | ------------ |
| **git restore** | **파일** (아직 커밋 안 한 수정)     | 파일 하나 Ctrl+Z             | 변화 없음               | ✅           |
| **git revert**  | **커밋 하나** 의 변경 내용          | 취소 내용을 적은 정정 기사   | 취소 커밋이 **새로 추가** | ✅ 안전      |
| **git reset**   | **브랜치 전체** 를 과거 커밋으로    | 타임머신                     | 이후 커밋이 **사라짐**  | ⚠️ 주의      |

---

### 1.1 실습 준비

깔끔한 상태에서 시작하기 위해 새 폴더를 만들고, 파일을 하나씩 만들며 커밋해 보자.

```bash
mkdir git-practice && cd git-practice
git init

# a 파일 만들고 커밋
echo "a" > a.txt
git add . && git commit -m "a 파일 생성"

# b 파일 만들고 커밋
echo "b" > b.txt
git add . && git commit -m "b 파일 생성"

# c 파일 만들고 커밋
echo "c" > c.txt
git add . && git commit -m "c 파일 생성"

git log --oneline
```

```
5e6f7a8 (HEAD -> main) c 파일 생성
3c4d5e6 b 파일 생성
1a2b3c4 a 파일 생성
```

- 앞의 `5e6f7a8` 같은 문자열이 **커밋 ID** 다. "이 커밋으로 되돌려 줘" 같은 명령은 이 ID로 한다. (실습할 때는 자기 화면에 나온 ID를 쓰자)
- 커밋 ID 대신 **`HEAD~1`(한 단계 전), `HEAD~2`(두 단계 전)** 처럼 상대적인 위치로 가리킬 수도 있다.

## 2. git restore : 파일 되돌리기

파일 하나가 잘못되었을 때, Ctrl+Z를 여러 번 눌러도 되지만 수정한 곳이 많다면 명령어 하나로 처리할 수 있다.

```bash
# c.txt를 아무렇게나 수정한 뒤

# 마지막 커밋 상태로 되돌리기 (수정한 내용은 버려짐 ⚠️)
git restore c.txt

# 특정 커밋 시점의 내용으로 파일 되돌리기
git restore --source 3c4d5e6 b.txt     # b 파일을 'b 파일 생성' 커밋 시점으로
git restore --source HEAD~2 b.txt      # 상대 위치로도 가능

# 스테이징만 취소 (수정 내용은 그대로 남음)
git restore --staged c.txt
```

- `git restore 파일`로 버린 수정 내용은 **커밋한 적이 없으므로 되살릴 수 없다.** 신중하게 쓰자.
- 예전에는 `git checkout -- 파일명`, `git reset HEAD 파일명`으로 같은 일을 했다. 지금은 역할이 분명한 `git restore`를 권장한다.

## 3. git revert : 커밋 취소하기 (기록을 남기며)

커밋 하나에서 일어난 변경만 취소하고 싶으면 `git revert`를 쓴다.
커밋을 지우는 게 아니라, **그 커밋의 변경을 정반대로 적용한 "취소 커밋"을 새로 만든다.**

```bash
# 'b 파일 생성' 커밋에서 일어난 일만 취소
git revert 3c4d5e6
```

```
main  A───B───C───B'   ← B를 취소하는 새 커밋 (B는 기록에 그대로 남아 있음)
```

![git_5_1](https://raw.githubusercontent.com/berenickt/image-server/main/img/git_5_1.png)

- 실행하면 커밋 메시지를 입력하는 에디터가 열린다. 기본 메시지(`Revert "b 파일 생성"`)를 그대로 두거나 고친 뒤, **저장하고 닫으면** 끝이다.
  - Vim이 열렸다면 `i`로 수정 → `Esc` → `:wq`로 저장하고 나간다. (VS Code를 기본 에디터로 쓰는 설정은 [01-설치](/devops/git/01-git-install) 참고)
- `git log --oneline`으로 확인하면 revert 커밋이 새로 생겼고, 작업 폴더에는 `a.txt`, `c.txt`만 남아 있다.
- **그 커밋 이후에 한 작업(c 파일)은 영향 없이 그대로 유지** 된다.

```bash
git revert 커밋ID1 커밋ID2      # 여러 커밋을 한 번에 취소 (각각 revert 커밋 생성)
git revert HEAD                 # 가장 최근 커밋 하나 취소
git revert --no-edit HEAD       # 메시지 수정 창 없이 바로 취소
git revert -m 1 merge커밋ID     # merge 커밋 취소 (-m 1 : 첫 번째 부모, 즉 main 쪽 기준으로 되돌림)
```

> 💡 revert는 **이력을 지우지 않고 "취소했다"는 기록을 추가** 하기 때문에, 이미 GitHub에 올려서 **다른 사람과 공유한 커밋을 되돌릴 때 가장 안전한 방법** 이다.

## 4. git reset : 과거 시점으로 돌아가기

`git reset`은 **브랜치를 특정 커밋 시점으로 통째로 되돌린다.** 그 이후의 커밋은 브랜치 이력에서 사라진다.

```bash
# 'b 파일 생성' 커밋 시점으로 완전히 되돌림 (작업 폴더의 파일까지)
git reset --hard 3c4d5e6

git log --oneline
# 3c4d5e6 (HEAD -> main) b 파일 생성
# 1a2b3c4 a 파일 생성
# → 'c 파일 생성' 커밋이 사라지고, c.txt 파일도 삭제됨
```

```
reset 전   main  A───B───C
reset 후   main  A───B          ← C는 더 이상 브랜치에 없음
```

> 지금까지의 기억을 다 포기하고 인생을 7살로 리셋해 준다면 돌아가겠는가?
> 인생이 어느 정도 궤도에 오른 사람이라면 돌아가기 어렵다.
>
> 마찬가지로 `git reset --hard`는 **프로젝트가 망했을 때나, 아주 짧은 거리를 되돌아갈 때** 만 쓰자.

### 4.1 reset의 세 가지 옵션 : --soft, --mixed, --hard

reset은 **되돌린 커밋들의 변경 내용을 어떻게 처리할지** 옵션으로 고를 수 있다.
실습 상태(a, b, c를 각각 커밋)에서 `'b 파일 생성'` 커밋으로 reset하면, 사라지는 커밋은 `'c 파일 생성'` 하나다. 이 **c의 변경 내용** 이 옵션마다 다르게 남는다.

| 옵션                   | 커밋 기록           | 스테이징 영역               | 작업 폴더 (실제 파일)     | 실습 결과                               |
| ---------------------- | ------------------- | --------------------------- | ------------------------- | --------------------------------------- |
| `--soft`               | b 시점으로 되돌림   | c의 변경이 **스테이징된 채** 남음 | 그대로 (a, b, c 있음) | 바로 다시 `git commit` 가능             |
| `--mixed` (기본값)     | b 시점으로 되돌림   | 비움 (스테이징 취소)         | 그대로 (a, b, c 있음)     | `git add` 부터 다시 해야 함 (c는 untracked) |
| `--hard`               | b 시점으로 되돌림   | 비움                        | **b 시점으로 되돌림** (c 삭제) | 변경 내용까지 모두 사라짐 ⚠️       |

```bash
git reset --soft 3c4d5e6    # 커밋만 취소, 변경은 스테이징 상태로 유지
git reset --mixed 3c4d5e6   # 커밋 + 스테이징 취소, 변경은 파일에 유지
git reset 3c4d5e6           # 옵션을 안 쓰면 --mixed
git reset --hard 3c4d5e6    # 커밋 + 스테이징 + 파일 변경까지 모두 버림
```

- 파일을 아예 지워 버리는 대신 **검토하고 다시 커밋하고 싶다면 `--soft`나 `--mixed`** 를 쓰자.
- 자주 쓰는 활용 : **방금 한 커밋을 취소하고 다시 하고 싶을 때**

```bash
git reset --soft HEAD~1     # 마지막 커밋만 취소 (변경은 스테이징 상태로 남음) → 다시 정리해서 커밋
```

### 4.2 협업 중에는 reset 금지

- **이미 GitHub에 올려서 공유한 커밋은 reset하지 않는다.** 동료의 저장소에는 그 커밋이 남아 있어서 이력이 어긋나고, 강제로 push하면 **다른 사람의 소스 코드가 사라질 수 있다.**
- 공유한 커밋을 되돌릴 때는 **`git revert`** 를 쓰자.
- reset은 아직 push하지 않은 **내 로컬 커밋을 정리할 때** 만 쓰는 것이 원칙이다.

### 4.3 untracked 파일과 git clean

- `git reset --hard`는 **Git이 추적하지 않는 파일(한 번도 `git add` 하지 않은 새 파일)** 은 건드리지 않는다.
- 이런 파일까지 지우려면 `git clean`을 쓴다.

```bash
git clean -n     # 무엇이 지워질지 미리 보기 (꼭 먼저 확인!)
git clean -f     # untracked 파일 삭제
git clean -fd    # untracked 폴더까지 삭제
```

## 5. 실수로 reset --hard 했다면 : git reflog

reset으로 사라진 커밋도 **바로 영구 삭제되지는 않는다.** Git은 HEAD가 이동한 기록을 **reflog** 에 일정 기간(기본 약 90일) 남겨 둔다.

```bash
git reflog
```

```
3c4d5e6 (HEAD -> main) HEAD@{0}: reset: moving to 3c4d5e6
5e6f7a8 HEAD@{1}: commit: c 파일 생성        ← 사라진 커밋이 여기 있다!
3c4d5e6 HEAD@{2}: commit: b 파일 생성
```

```bash
git reset --hard 5e6f7a8    # 사라졌던 'c 파일 생성' 시점으로 다시 돌아오기
```

- reflog는 **내 컴퓨터에만** 있는 기록이다. 다른 사람의 저장소나 GitHub에는 없다.
- 한 번도 커밋하지 않은 변경은 reflog에도 없으므로 되살릴 수 없다. → **자주 커밋하는 습관** 이 최고의 보험이다.

## 6. 이럴 땐 이렇게

| 상황                                                         | 명령어                                      |
| ------------------------------------------------------------ | ------------------------------------------- |
| 파일을 잘못 고쳤다. 마지막 커밋 상태로 되돌리고 싶다         | `git restore 파일`                          |
| `git add`를 잘못했다. 스테이징만 취소하고 싶다               | `git restore --staged 파일`                 |
| 방금 커밋 메시지에 오타가 있다 (push 전)                     | `git commit --amend -m "새 메시지"`         |
| 방금 커밋에 파일 하나를 빠뜨렸다 (push 전)                   | `git add 파일` → `git commit --amend --no-edit` |
| 방금 한 커밋을 취소하고 다시 정리하고 싶다 (push 전)         | `git reset --soft HEAD~1`                   |
| 최근 커밋 몇 개를 완전히 버리고 싶다 (push 전)               | `git reset --hard HEAD~2`                   |
| **이미 push한** 커밋을 되돌리고 싶다                         | `git revert 커밋ID`                         |
| 합친(merge) 브랜치를 되돌리고 싶다 (push 후)                 | `git revert -m 1 merge커밋ID`               |
| reset --hard로 날린 커밋을 되살리고 싶다                     | `git reflog` → `git reset --hard 커밋ID`    |
| add 안 한 새 파일들을 모두 지우고 싶다                       | `git clean -n` 확인 → `git clean -fd`       |

> 💡 기준은 하나다. **"이미 다른 사람과 공유(push)했는가?"**
>
> - 공유 전 : `reset`, `commit --amend`로 자유롭게 정리해도 된다.
> - 공유 후 : `revert`로 **기록을 남기며** 되돌린다.
