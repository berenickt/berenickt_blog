## 1. Git을 왜 쓸까?

코드를 짜든, 디자인을 하든, 보고서를 쓰든 **파일의 변경 내역을 보존하고 관리하는 일** 이 필요하다.

```
2023-01-11-디자인 시안_최종
2023-01-12-디자인 시안_최종의 최종
2023-01-13-디자인 시안_최종의 최종2
2023-01-14-디자인 시안_진짜 마지막
```

> Q. 이틀 전 코드로 되돌아가려면?
>
> 1. 매일 직접 파일을 복사해서 백업해 두기 → 귀찮고, 무엇이 바뀌었는지 알 수 없다.
> 2. **버전 관리 소프트웨어 쓰기** → 복사본을 만들지 않고도 깔끔하게 버전을 관리할 수 있다.

Git은 리눅스를 만든 **리누스 토르발스(Linus Torvalds)가 2005년에 만든 분산 버전 관리 도구** 다. 지금은 개발자 대부분이 쓰는 사실상의 표준이다.
(Git이 탄생한 배경은 [버전 관리 도구의 역사 및 발전](/devops/git) 참고)

### 1.1 Git으로 할 수 있는 것

| 할 수 있는 일                 | 예시                                                         |
| ----------------------------- | ------------------------------------------------------------ |
| **이력 기록**                 | "로그인 버튼 추가"처럼 의미 있는 단위로 변경을 저장(커밋)    |
| **되돌리기**                  | 버그가 생기기 전 상태로 파일이나 프로젝트 전체를 되돌림      |
| **변경 비교**                 | 어제와 오늘 코드에서 무엇이 바뀌었는지 한 줄 단위로 확인     |
| **원인 추적**                 | 이 줄을 누가, 언제, 왜 바꿨는지 확인 (`git blame`, `git log`) |
| **브랜치**                    | 원본은 그대로 두고 새 기능을 따로 실험한 뒤 합치기           |
| **협업**                      | 여러 사람이 같은 프로젝트를 동시에 고치고 합치기 (GitHub 등) |
| **백업**                      | 원격 저장소(GitHub)에 올려 두면 컴퓨터가 고장 나도 안전       |

---

### 1.2 미리 알아 두면 좋은 개념

Git을 쓰면 프로젝트 폴더는 다음 세 영역으로 나뉜다.

```
작업 폴더 (Working Directory)   →   스테이징 영역 (Staging Area)   →   저장소 (Repository)
   파일을 실제로 수정하는 곳           커밋할 변경을 골라 담는 곳            커밋(이력)이 저장되는 곳
                        git add                              git commit
```

- **저장소(Repository)** : 이력이 저장되는 곳. 프로젝트 폴더 안의 숨김 폴더 `.git`이 저장소다.
- **커밋(Commit)** : 특정 시점의 프로젝트 상태를 저장한 스냅샷. 각 커밋은 고유한 해시(`a1b2c3d`)를 가진다.
- **브랜치(Branch)** : 독립적인 작업 줄기. 기본 브랜치는 보통 `main`
- **원격 저장소(Remote)** : GitHub 같은 서버에 있는 저장소. `push`로 올리고 `pull`로 받는다.

각 개념은 이 시리즈의 다음 글부터 하나씩 실습한다. → [02-버전 기록과 비교 : add, commit, diff](/devops/git/02-add-commit-diff)

> 💡 **Git과 GitHub는 다르다.**
>
> - **Git** : 내 컴퓨터에서 버전을 관리하는 **프로그램**
> - **GitHub** : Git 저장소를 인터넷에 올려 두고 공유·협업하는 **웹 서비스** (GitLab, Bitbucket도 같은 종류)

## 2. Git 설치

설치 후 터미널에서 다음 명령어로 확인한다. 버전이 나오면 성공이다.

```bash
git --version
# git version 2.x.x
```

### 2.1 Windows

[git-scm.com/download/win](https://git-scm.com/download/win)에서 설치 파일을 받아 실행한다. (또는 터미널에서 `winget install --id Git.Git -e`)

설치 화면에서 바꾸면 좋은 옵션은 두 가지다. 나머지는 기본값으로 두면 된다.

1. **기본 에디터 선택** : 기본값이 Vim으로 되어 있으면, **Use Visual Studio Code as Git's default editor** 로 변경
   - 커밋 메시지를 쓸 때 익숙한 VS Code가 열린다.
2. **기본 브랜치 이름** : **Override the default branch name for new repositories** 를 선택하고 `main` 입력
   - 예전에는 `master`를 썼지만, 지금은 GitHub를 비롯해 대부분 `main`을 쓴다.

설치하면 **Git Bash** 라는 터미널도 함께 설치된다. 리눅스·맥과 같은 명령어(`ls`, `cat` 등)를 쓸 수 있어서 편하다.

### 2.2 macOS

맥에는 Xcode 명령줄 도구와 함께 Git이 들어 있다. 터미널에서 `git --version`을 입력했을 때 설치 안내 창이 뜨면 설치하면 된다.

```bash
xcode-select --install   # Apple이 제공하는 Git 설치
```

최신 버전을 쓰고 싶다면 **Homebrew** 로 설치한다.

```bash
# Homebrew가 없다면 먼저 설치 (https://brew.sh)
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

brew install git   # Git 설치
brew upgrade git   # 나중에 업데이트할 때
```

### 2.3 Linux

```bash
sudo apt install git   # Ubuntu, Debian
sudo dnf install git   # Fedora, Amazon Linux, RHEL
```

## 3. 처음 한 번 해 두는 설정

Git 설정은 사용자 홈 폴더의 **`.gitconfig`** 파일에 저장된다. `--global`은 "이 컴퓨터의 모든 저장소에 적용"이라는 뜻이다.

### 3.1 이름과 이메일 (필수)

커밋마다 **누가 만들었는지** 기록되므로, 처음에 꼭 등록해야 한다.

```bash
git config --global user.name "Beren"              # 자기가 쓸 이름
git config --global user.email "you@example.com"   # 자기 이메일 (GitHub 계정 이메일 권장)

# 확인
git config user.name    # Beren
git config user.email   # you@example.com
```

> 💡 GitHub에 올린 커밋의 이메일은 **누구나 볼 수 있다.** 개인 이메일을 공개하고 싶지 않다면,
> GitHub **Settings → Emails** 에서 제공하는 `숫자+아이디@users.noreply.github.com` 주소를 쓰면 된다.

### 3.2 에디터와 기본 브랜치

```bash
# 커밋 메시지 등을 VS Code로 작성 (--wait : VS Code 창을 닫을 때까지 터미널이 기다림)
git config --global core.editor "code --wait"

# 새 저장소의 기본 브랜치를 main으로 (설치할 때 안 했다면)
git config --global init.defaultBranch main
```

- `code` 명령이 안 된다면 VS Code에서 `Cmd/Ctrl + Shift + P` → **Shell Command: Install 'code' command in PATH** 를 실행한다.

### 3.3 설정 확인하기

```bash
git config --list                   # 모든 설정 보기 (목록이 길면 q를 눌러 빠져나오기)
git config --list --show-origin     # 각 설정이 어느 파일에서 왔는지까지 보기
git config --global -e              # .gitconfig 파일을 에디터로 열어 직접 수정
```

설정은 세 단계가 있고, 아래로 갈수록 우선순위가 높다.

| 범위       | 옵션         | 적용 대상               | 저장 위치                 |
| ---------- | ------------ | ----------------------- | ------------------------- |
| 시스템     | `--system`   | 컴퓨터의 모든 사용자    | Git 설치 폴더             |
| 사용자     | `--global`   | 내 계정의 모든 저장소   | `~/.gitconfig`            |
| 저장소     | `--local`    | 현재 저장소만           | 저장소의 `.git/config`    |

- e.g. 회사 프로젝트에서만 회사 이메일을 쓰고 싶다면, 그 저장소 안에서 `git config user.email "me@company.com"`(local)을 설정한다.

## 4. 줄바꿈 설정 (core.autocrlf)

> **CR, LF, CRLF**
>
> - `CR(Carriage Return, \r)` : 커서를 줄의 맨 앞으로 옮기는 동작
> - `LF(Line Feed, \n)` : 한 줄 아래로 내리는 동작
> - `CRLF(\r\n)` : 둘을 합친 줄바꿈
>
> 타자기에서 온 개념이다. 종이를 한 줄 올리고(LF), 타자 위치를 맨 앞으로 되돌려야(CR) 다음 줄을 쓸 수 있었다.

운영체제마다 줄바꿈 문자가 다르다.

- **Windows** : `CRLF` (`\r\n`)
- **macOS, Linux** : `LF` (`\n`)

그래서 여러 운영체제를 쓰는 팀에서는 **내가 내용을 바꾸지 않았는데도 줄바꿈 문자 때문에 파일 전체가 바뀐 것처럼** 보여서, 변경 이력(`git diff`, `git blame`)을 보기 어려워진다.

이를 자동으로 맞춰 주는 설정이 `core.autocrlf` 다.

```bash
# Windows : 저장소에 넣을 때 CRLF → LF, 꺼낼 때 LF → CRLF
git config --global core.autocrlf true

# macOS / Linux : 저장소에 넣을 때 CRLF → LF로만 변환 (꺼낼 때는 그대로)
git config --global core.autocrlf input
```

- 결과적으로 **저장소 안에는 항상 LF** 로 저장되고, 각자의 컴퓨터에서는 자기 운영체제에 맞는 줄바꿈을 쓰게 된다.
- 이 설정을 하면 `git add` 할 때 다음과 같은 경고가 보일 수 있는데, 변환이 일어난다는 안내일 뿐 문제가 아니다.

```
warning: LF will be replaced by CRLF in bora.txt.
(경고 : bora.txt의 LF가 CRLF로 바뀝니다.)
```

### 4.1 팀 프로젝트라면 `.gitattributes`

`core.autocrlf`는 **각자 컴퓨터의 설정** 이라서, 팀원 중 한 명이라도 설정을 안 하면 문제가 다시 생긴다.
그래서 팀 프로젝트에서는 저장소에 **`.gitattributes`** 파일을 두어 규칙을 함께 관리하는 것이 더 확실하다.

```gitattributes
# 텍스트 파일은 저장소에 LF로 저장
* text=auto eol=lf

# Windows 전용 스크립트는 CRLF 유지
*.bat text eol=crlf

# 바이너리 파일은 변환하지 않음
*.png binary
*.jpg binary
```

에디터에서도 줄바꿈을 LF로 맞춰 두면 좋다. (VS Code 오른쪽 아래 상태 표시줄의 `CRLF`/`LF`, 또는 `.editorconfig`의 `end_of_line = lf`)

## 5. GitHub 연결 준비

GitHub에 코드를 올리려면(push) **인증** 이 필요하다. GitHub는 2021년부터 **계정 비밀번호로는 push할 수 없다.**
다음 중 하나로 설정하자.

### 5.1 GitHub CLI로 로그인 (가장 쉬움)

```bash
# 설치 : macOS는 brew install gh, Windows는 winget install --id GitHub.cli
gh auth login   # 안내에 따라 브라우저로 로그인하면 Git 인증까지 자동 설정
```

- Windows용 Git에는 **Git Credential Manager** 가 포함되어 있어서, 처음 push할 때 뜨는 브라우저 로그인 창으로 인증해도 된다.

### 5.2 SSH 키 사용

```bash
ssh-keygen -t ed25519 -C "you@example.com"   # 키 생성 (엔터로 기본 위치에 저장)
cat ~/.ssh/id_ed25519.pub                     # 공개 키 출력 → 복사
```

1. GitHub **Settings → SSH and GPG keys → New SSH key** 에 공개 키(`.pub`)를 붙여 넣는다.
2. 연결 확인 : `ssh -T git@github.com` → `Hi 아이디! You've successfully authenticated...`
3. 이후 저장소 주소를 `git@github.com:아이디/저장소.git` 형태로 쓰면 된다.

> ⚠️ `.pub`이 붙지 않은 **개인 키(`id_ed25519`)는 절대 다른 사람에게 보여 주거나 업로드하지 말자.**

## 6. Git을 쓰는 도구들

명령어를 먼저 익히는 것을 권장하지만, 화면으로 보는 도구도 함께 쓰면 이해가 빠르다.

- **VS Code 소스 제어 탭** : 변경 파일 확인, 스테이징, 커밋, 충돌 해결을 에디터 안에서
- **GitHub Desktop** : 가장 쉬운 GUI 도구
- **GitKraken, Fork, Sourcetree** : 브랜치 그래프를 보기 좋게 보여 주는 GUI 도구

> 💡 Git 2.23부터 `git checkout` 하나가 하던 일을 **`git switch`**(브랜치 이동)와 **`git restore`**(파일 되돌리기)로 나눴다.
> 이 시리즈에서는 이해하기 쉬운 새 명령어를 기준으로 설명한다.
