## 3. 왜 한국에서는 Java·Spring을 많이 쓸까?

### 3.1 Spring의 탄생

- 예전에는 자바로 서버를 만들 때 **Java EE(기업용 자바, 지금의 Jakarta EE)** 를 썼는데, 설정이 복잡하고 무거웠다.
- 로드 존슨(Rod Johnson)이 이를 개선하자고 제안하며 만든 것이 **Spring 프레임워크** (2003년)다.
  - 이름도 Java EE라는 "겨울"이 끝나고 "봄"이 왔다는 의미에서 Spring
- 이후 복잡한 설정을 자동화한 **Spring Boot** (2014년)가 나오면서 사실상 표준이 되었다.

### 3.2 정적 타입과 대규모 개발

- Java·Kotlin은 **정적 타입 언어** 라서, 컴파일 시점에 많은 오류를 잡고 IDE의 자동 완성·리팩터링 지원이 강력하다.
  - 수십~수백 명이 같은 코드를 오래 유지보수하는 대규모 시스템에서 특히 유리하다.
- 다만 JavaScript도 **TypeScript** 로, Python도 **타입 힌트 + 타입 검사기** 로 상당 부분 보완할 수 있다.

### 3.3 실행 방식

- Java·Kotlin은 바이트코드로 컴파일된 뒤 **JVM** 에서 실행되며, JVM의 JIT 컴파일러가 자주 실행되는 코드를 기계어로 바꿔 빠르게 실행한다.
- JavaScript(V8 엔진)도 **실행 중에 JIT 컴파일** 로 최적화한다. 그래서 단순 처리 속도는 생각보다 차이가 크지 않다.
- Python(CPython)은 기본적으로 인터프리터 방식이라 순수 연산은 느린 편이지만, 무거운 계산은 C로 만든 라이브러리(NumPy 등)가 처리하고, 웹 서버는 대부분 DB·네트워크를 기다리는 시간이 더 길어서 실무에서 큰 문제가 되지 않는 경우가 많다.
- 결국 웹 서버 성능은 언어 자체보다 **DB 설계, 캐싱, 아키텍처** 에 훨씬 크게 좌우된다.

### 3.4 생태계와 안정성

- Spring은 기업용 애플리케이션에 필요한 도구(보안, 트랜잭션, 배치, 메시징, 모니터링 등)를 거의 다 갖추고 있다.
- 대규모 서비스는 "단 1초, 단 1명도 장애를 겪어서는 안 된다"는 요구를 받는다.
  - 검증되지 않은 서드파티 라이브러리로 모험하기보다, **이미 수많은 기업이 써서 검증된 도구** 를 쓰는 게 합리적이라는 판단이 많다.
- 그렇다고 다른 언어로 대규모 서비스를 못 만드는 것은 아니다.
  - 페이스북(메타)은 PHP를 개량한 Hack 언어를, 인스타그램은 Python(Django)을, 드롭박스는 Python(이후 일부 Go·Rust)을 쓴다.
  - 트위치는 Ruby on Rails로 시작해 Go로 옮겼다.
  - 언어보다 **설계와 운영 역량** 이 규모를 결정한다.

### 3.5 채용 시장 : 가장 근본적인 이유

- 어떤 트래픽에 어떤 언어를 써야만 한다는 정답은 없다. 실력 있는 개발자가 있으면 어떤 언어로도 잘 돌아간다.
- 국내 시장에서 Java·Spring이 많은 가장 큰 이유는 **경력자를 구하기 쉽기 때문** 이다.
  - 2000년대 후반 Java·Spring 기반의 **전자정부 표준 프레임워크** 가 나오면서, 공공기관과 관련된 SI 회사들이 자바를 표준으로 쓰게 되었다.
  - IT 산업이 커지며 기업들이 경력자를 대거 필요로 했고, 가장 많은 경력자가 아는 Java·Spring이 자연스럽게 메인이 되었다.
- 그 결과 지금도 국내 대기업·금융·커머스·빅테크의 백엔드 채용 공고는 **Java/Kotlin + Spring** 비중이 압도적으로 높다.

## 4. 회사 규모·분야별 경향 (2026년)

| 구분                         | 주로 쓰는 스택                                       | 이유                                                |
| ---------------------------- | ---------------------------------------------------- | --------------------------------------------------- |
| 대기업·금융·공공·SI          | Java + Spring Boot                                   | 검증된 안정성, 경력자 풀, 레거시                     |
| 빅테크·커머스·핀테크         | **Kotlin** + Spring Boot (Java와 혼용)               | 간결한 문법, null 안정성, Java 생태계 그대로 사용     |
| 스타트업·웹 서비스           | TypeScript(NestJS 등), Kotlin + Spring               | 빠른 개발, 프론트엔드와 언어 통일, 풀스택 채용        |
| AI·데이터 서비스             | Python (FastAPI)                                     | AI 모델·라이브러리 생태계가 Python 중심              |
| 인프라·플랫폼·고성능         | Go, (일부) Rust                                      | 동시성, 낮은 리소스 사용, 클라우드 도구 생태계        |
| 게임                         | C#(.NET), C++, Go, Java                              | 게임 엔진·클라이언트 언어와 맞춤                     |

- **Kotlin** 은 최근 국내 테크 기업과 스타트업에서 Spring과 함께 빠르게 늘고 있다. Java를 배운 뒤 넘어가기 쉽다.
- 스타트업이라고 모두 Node를 쓰는 것은 아니다. 처음부터 Kotlin + Spring으로 시작하는 곳도 많고, 성장하면서 Node에서 Spring으로 옮기는 경우도 있다. (5장 사례)
- 반대로 Spring도 계속 진화하고 있다. Java 21의 **가상 스레드(Virtual Threads)** 로 적은 자원으로 많은 동시 요청을 처리할 수 있게 되었고, GraalVM 네이티브 이미지로 시작 속도·메모리 문제를 줄이는 방법도 생겼다.

## 5. 사례

- **지그재그** : 처음에는 전부 Node.js로 시작했다.
  - 2022년 카카오에 인수되기 전까지 Node 프로젝트가 여럿 있었고,
  - 이후 쿠팡·배민·네이버 출신의 Java·Spring 시니어 개발자들이 합류하면서 점차 전환,
  - 2022년에 Node 프로젝트를 모두 정리하고 Java·Spring으로 전환했다.
  - → 기술 선택에는 기술적 이유만큼 **조직과 채용** 이 큰 영향을 준다는 사례

## 6. 그래서 무엇을 배워야 할까?

```
목표가 분명한가?
├─ 국내 대기업·금융·커머스·빅테크 취업 → Java(+Kotlin) + Spring Boot ✅
├─ 스타트업, 풀스택(프론트엔드도 함께) → TypeScript + NestJS (Node.js) ✅
├─ AI·데이터 관련 서비스 → Python + FastAPI
├─ 인프라·클라우드·고성능 서버 → Go
└─ 아직 모르겠다
     → 국내 채용 공고 20~30개를 직접 읽어 보고, 가장 많이 보이는 스택으로 시작
       (대부분의 경우 Java + Spring, 그다음이 Node.js)
```

- **하나를 깊게** 하는 것이 여러 개를 얕게 하는 것보다 훨씬 낫다.
- 두 번째 언어는 첫 번째 언어로 실제 서비스를 하나 만들어 배포해 본 뒤에 배워도 늦지 않다.
- 프론트엔드 경험이 있다면 Node.js로 백엔드 개념을 빠르게 익힌 뒤, 필요에 따라 Spring으로 넓히는 것도 좋은 경로다.

## 7. 본질 : 언어보다 중요한 것

- 백엔드 개발의 본질은 **"네트워크와 DB를 얼마나 잘 이해하고, 이를 어떻게 응용할 수 있는가"** 다.
  - HTTP, 트랜잭션, 인덱스, 캐싱, 동시성, 장애 대응… 이 개념들은 어떤 언어를 쓰든 똑같다.
- 지금 쓰는 프레임워크가 언젠가는 저물 수 있다는 생각으로 접근하자.
  - 핵심 개념을 잘 이해하고 있다면, 다른 프레임워크로 옮겨 가는 건 어렵지 않다.
- "지금 하던 걸 버리고 스프링을 다시 배울까?"가 고민된다면, 먼저 **"지금 하던 걸 더 깊게 파서 수준 높은 경험을 쌓을 수 없을까?"** 를 생각해 보자.
- Django, Node, Spring 무엇을 쓰든, **설계만 잘하면 전 세계 규모의 트래픽도 처리할 수 있다.**
- 크게 성장한 회사들은 하나의 언어만 쓰지 않는다.
  - 처음 만든 시스템(레거시)은 그대로 가져가는 경우가 많지만, 새로 만드는 시스템은 목적에 맞게 여러 언어를 섞어 쓴다.
- 사람마다 살아가는 방식이 다르듯, **"이것만이 정답"인 선택은 없다.**
