## 1. UI 라이브러리란?

버튼, 모달, 드롭다운, 탭, 날짜 선택기처럼 **어느 서비스에나 필요한 UI 요소를 미리 만들어 둔 컴포넌트 모음** 이다.

직접 만들면 생각보다 할 일이 많다.

- 모달 하나만 해도 : 열릴 때 포커스 이동, `Esc`로 닫기, 바깥 클릭 처리, 스크롤 잠금, 닫으면 원래 버튼으로 포커스 복귀, 스크린 리더용 속성(`role="dialog"`, `aria-modal`)...
- 드롭다운·콤보박스는 키보드 탐색, 화면 밖으로 넘칠 때 위치 조정까지 필요하다.

UI 라이브러리는 이런 **동작과 접근성** 을 검증된 형태로 제공해 주기 때문에, 개발자는 서비스 고유의 기능에 집중할 수 있다.

## 2. UI 라이브러리의 3가지 유형

| 유형             | 제공하는 것             | 대표 예시                                   | 장점                          | 단점                                |
| ---------------- | ----------------------- | ------------------------------------------- | ----------------------------- | ----------------------------------- |
| **완성형**       | 동작 + 디자인           | MUI, Ant Design, Mantine, Chakra UI         | 설치하면 바로 예쁜 화면       | 우리 디자인으로 바꾸기 어렵고 무거움 |
| **Headless**     | 동작 + 접근성 (스타일 X) | Radix UI, React Aria, Base UI, Ark UI       | 디자인 자유도 100%            | 스타일을 전부 직접 입혀야 함        |
| **코드 복사형**  | 컴포넌트 소스 코드      | **shadcn/ui**                               | 내 코드라서 마음대로 수정     | 업데이트를 직접 반영해야 함         |

- 2020년 무렵까지는 **완성형** 이 대세였다. (Bootstrap → Material UI, Ant Design)
- 이후 회사마다 자체 디자인 시스템을 만들면서 **Headless** 가 떠올랐고,
- 지금은 Headless 위에 Tailwind로 스타일을 입힌 코드를 복사해 쓰는 **shadcn/ui 방식** 이 React 진영에서 가장 많이 쓰인다.

## 3. 완성형 UI 라이브러리

| 라이브러리                                    | 특징                                                                                     | 잘 맞는 곳                         |
| --------------------------------------------- | ---------------------------------------------------------------------------------------- | ---------------------------------- |
| [MUI (Material UI)](https://mui.com/) ✅      | 구글 Material Design 기반, 가장 오래되고 큰 React UI 라이브러리. 데이터 그리드, 날짜 선택기 등 고급 컴포넌트(MUI X) | 대시보드, 사내 서비스              |
| [Ant Design](https://ant.design/)             | 알리바바 제작. 테이블·폼·트리 등 **관리자 화면용 컴포넌트가 매우 풍부**                 | 어드민, B2B 서비스                 |
| [Mantine](https://mantine.dev/)               | 컴포넌트 100개 이상 + 유용한 훅 모음. 문서가 친절하고 커스터마이즈가 쉬움               | 개인·스타트업 프로젝트             |
| [Chakra UI](https://chakra-ui.com/)           | 스타일 props(`<Box p={4} color="red.500">`)로 빠르게 작성. v3부터 Ark UI + Panda CSS 기반 | 빠른 프로토타입                    |
| [HeroUI](https://www.heroui.com/) (구 NextUI) | Tailwind 기반의 완성형 디자인, 애니메이션이 매끄러움                                    | Tailwind를 쓰는 프로젝트           |
| [React Bootstrap](https://react-bootstrap.github.io/) | Bootstrap 디자인을 React 컴포넌트로 제공                                          | Bootstrap에 익숙한 팀, 기존 프로젝트 |

선택할 때 볼 것

- **런타임 CSS-in-JS 의존 여부** : MUI(Emotion 기반), Chakra UI v2 등은 React 서버 컴포넌트에서 `'use client'`가 필요하다. → [Styling 라이브러리](/frontend/styling)
- **번들 크기** : 필요한 컴포넌트만 가져와도(tree shaking) 기본 무게가 있다.
- **디자인 변경 가능 범위** : 테마(색, 폰트, 간격)만 바꿀 것인지, 컴포넌트 모양 자체를 바꿀 것인지

## 4. Headless UI 라이브러리

**동작과 접근성만 제공하고, 생김새는 전혀 정하지 않는** 라이브러리다.
디자이너가 만든 우리 서비스만의 디자인 시스템을 구현할 때 가장 많이 쓴다.

```tsx
import * as Dialog from '@radix-ui/react-dialog'

// 포커스 이동, Esc 닫기, 스크롤 잠금, aria 속성은 Radix가 처리
// 생김새(className)는 내가 정한다
<Dialog.Root>
  <Dialog.Trigger className="btn">열기</Dialog.Trigger>
  <Dialog.Portal>
    <Dialog.Overlay className="fixed inset-0 bg-black/50" />
    <Dialog.Content className="fixed left-1/2 top-1/2 rounded-xl bg-white p-6">
      <Dialog.Title>제목</Dialog.Title>
      <Dialog.Close>닫기</Dialog.Close>
    </Dialog.Content>
  </Dialog.Portal>
</Dialog.Root>
```

| 라이브러리                                            | 특징                                                                   |
| ----------------------------------------------------- | ---------------------------------------------------------------------- |
| [Radix UI](https://www.radix-ui.com/) ✅              | 가장 널리 쓰이는 Headless 라이브러리, shadcn/ui의 기반                  |
| [React Aria](https://react-spectrum.adobe.com/react-aria/) | 어도비 제작. **접근성과 국제화(다국어·RTL)** 가 가장 꼼꼼함          |
| [Base UI](https://base-ui.com/)                       | Radix·MUI·Floating UI 제작진이 만든 차세대 Headless 라이브러리. shadcn/ui에서도 Radix 대신 선택 가능 |
| [Ark UI](https://ark-ui.com/)                         | 상태 머신(Zag.js) 기반. React·Vue·Solid·Svelte를 모두 지원             |
| [Headless UI](https://headlessui.com/)                | Tailwind CSS 팀 제작. 컴포넌트 수는 적지만 Tailwind와 궁합이 좋음       |

## 5. 코드 복사형 : shadcn/ui

[shadcn/ui](https://ui.shadcn.com/)는 npm으로 설치하는 라이브러리가 아니다.
**Radix UI(또는 Base UI) + Tailwind CSS로 만든 컴포넌트 코드를 CLI로 내 프로젝트에 복사** 해 준다.

```bash
npx shadcn@latest init
npx shadcn@latest add button dialog
# → components/ui/button.tsx, components/ui/dialog.tsx 파일이 생긴다
```

- 장점
  - 코드가 **내 프로젝트 안에** 있어서, 디자인이든 동작이든 마음대로 고칠 수 있다.
  - 쓰는 컴포넌트만 들어오므로 가볍다.
  - 접근성은 Radix/Base UI가 보장한다.
  - 사용자가 워낙 많아서, AI 코딩 도구도 shadcn/ui 코드를 잘 만든다.
- 단점
  - 원본이 업데이트되어도 자동으로 반영되지 않는다.
  - Tailwind를 쓰지 않는 프로젝트에는 맞지 않는다.
- 같은 방식으로 컴포넌트를 배포하는 **레지스트리(registry)** 생태계가 생겨서, 다른 사람이 만든 블록·컴포넌트도 같은 CLI로 가져올 수 있다.

cf. [Tailwind CSS](/frontend/tailwindcss/01-tailwindcss)

## 6. 목적별 라이브러리

UI 라이브러리 하나로 모든 걸 해결하기보다는, 필요한 영역마다 전문 라이브러리를 함께 쓰는 경우가 많다.

### 6.1 애니메이션

| 라이브러리                                     | 특징                                                                                 |
| ---------------------------------------------- | ------------------------------------------------------------------------------------ |
| [Motion](https://motion.dev/) ✅ (구 Framer Motion) | React 애니메이션의 사실상 표준. `<motion.div animate={{ x: 100 }} />`, 레이아웃·퇴장 애니메이션. 2024년 Framer에서 독립하며 이름이 바뀌었고, React 없이도 사용 가능 |
| [React Spring](https://www.react-spring.dev/)  | 물리 기반(스프링) 애니메이션으로 자연스러운 움직임                                    |
| [GSAP](https://gsap.com/)                      | 복잡한 타임라인·스크롤 애니메이션의 강자. Webflow 인수 후 **모든 플러그인이 무료** 가 되었다 |
| [Lottie](https://airbnb.io/lottie/)            | 디자이너가 After Effects로 만든 애니메이션을 JSON으로 재생                            |
| [AutoAnimate](https://auto-animate.formkit.com/) | 한 줄로 목록 추가·삭제 애니메이션                                                   |

> 간단한 전환은 CSS `transition`과 **View Transitions API** 로도 충분하다. 라이브러리는 꼭 필요할 때만.

### 6.2 그 밖에 자주 쓰는 것

- **아이콘** : [Lucide](https://lucide.dev/) (shadcn/ui 기본), [React Icons](https://react-icons.github.io/react-icons/), [Heroicons](https://heroicons.com/)
- **차트** : [Recharts](https://recharts.org/), [Chart.js](https://www.chartjs.org/), [Apache ECharts](https://echarts.apache.org/), [Nivo](https://nivo.rocks/)
- **테이블** : [TanStack Table](https://tanstack.com/table) (Headless), [AG Grid](https://www.ag-grid.com/), MUI X Data Grid
- **폼** : [React Hook Form](https://react-hook-form.com/) + [Zod](https://zod.dev/)
- **토스트 알림** : [Sonner](https://sonner.emilkowal.ski/), [react-hot-toast](https://react-hot-toast.com/)
- **날짜 선택** : [React Day Picker](https://daypicker.dev/)
- **팝업 위치 계산** : [Floating UI](https://floating-ui.com/) (툴팁·드롭다운이 화면 밖으로 넘치지 않게)
- **모바일 앱 스타일 UI** : [Ionic](https://ionicframework.com/), [Konsta UI](https://konstaui.com/)

## 7. 무엇을 골라야 할까?

```
디자이너가 만든 자체 디자인 시스템이 있는가?
├─ YES → Headless(Radix UI, React Aria, Base UI) + 우리 스타일
│        └─ Tailwind를 쓴다면 → shadcn/ui로 시작해서 우리 디자인으로 수정 ✅
└─ NO
   ├─ 관리자 화면, 테이블·폼이 많은 B2B 서비스 → Ant Design, MUI
   ├─ 빠르게 그럴듯한 서비스를 만들고 싶다 → shadcn/ui ✅, Mantine
   └─ Bootstrap 디자인이 익숙하다 → React Bootstrap
```

공통으로 확인할 것

1. **접근성** : 키보드 조작, 스크린 리더 지원이 되는가?
2. **유지보수 상태** : 최근 릴리스, 이슈 대응, React 최신 버전 지원
3. **서버 컴포넌트 호환** : Next.js App Router를 쓴다면 특히 중요
4. **커스터마이즈 범위** : 테마만 바꾸면 되는지, 모양 자체를 바꿔야 하는지
5. **번들 크기와 의존성**

## 8. 새 라이브러리를 익히는 방법

- 필요에 따라 라이브러리를 찾고 **대안(alternatives)** 과 비교한다. ([npm trends](https://npmtrends.com/), GitHub 스타·최근 커밋)
- 공식 문서로 라이브러리의 목적과 철학을 파악한다. (Introduction)
- 공식 문서대로 설치한다. (Installation)
- 공식 예제(Examples)를 따라 해 보고, API 문서를 보며 내 프로젝트에 적용한다.

라이브러리의 트렌드는 빠르게 변한다.
2년 전에 당연했던 선택이 지금은 당연하지 않다. (이 글을 처음 쓴 2023년에서 지금까지만 해도 완성형 → Headless → shadcn/ui로 흐름이 바뀌었다.)
결국 **스스로 새로운 라이브러리를 적용해 보는 능력(경험)** 이 관건이다.

라이브러리 적용에 정답은 없다. 맞는 것도 없지만 틀린 것도 없다.
만든 이의 설명과 가이드에 따라 내 프로젝트에 잘 적용했다면 그것으로 성공이다.
계속 시도하고, 반복하고, 새로운 기술에 대한 호기심으로 Just do it!
