## 1. 인터랙티브 웹이란?

사용자의 스크롤, 마우스, 터치에 반응해 **움직이고 변하는 화면** 을 만드는 분야다.

- e.g. 스크롤하면 제품이 회전하는 애플 제품 페이지, 마우스를 따라 움직이는 3D 오브젝트, 게임 같은 브랜드 사이트, 데이터 시각화, 웹 게임
- 마케팅·브랜드 사이트, 포트폴리오, 제품 소개 페이지에서 특히 많이 쓰인다.
- 일반 서비스 화면에서도 버튼 피드백, 페이지 전환, 목록 추가·삭제처럼 **작은 애니메이션(마이크로 인터랙션)** 이 사용자 경험을 크게 좌우한다.

---

### 1.1 웹에서 그래픽을 그리는 방법

| 기술              | 그리는 방식                                  | 잘 맞는 것                                   |
| ----------------- | -------------------------------------------- | -------------------------------------------- |
| **HTML + CSS**    | DOM 요소를 CSS로 변형·애니메이션             | UI 애니메이션, 페이지 전환, 스크롤 효과      |
| **SVG**           | 벡터(선·도형)를 DOM 요소로                   | 아이콘, 일러스트 애니메이션, 차트            |
| **Canvas 2D**     | 픽셀을 JS로 직접 그림                        | 파티클, 그림판, 2D 게임, 대량의 점·선        |
| **WebGL**         | GPU로 3D 그래픽 렌더링                       | 3D 모델, 셰이더 효과                         |
| **WebGPU**        | WebGL의 차세대, 최신 GPU 기능 활용           | 고성능 3D, GPU 연산(머신러닝, 시뮬레이션)    |

- **DOM 기반(HTML, CSS, SVG)** 은 다루기 쉽고 접근성·SEO가 좋지만, 요소가 수천 개가 넘으면 느려진다.
- **Canvas·WebGL** 은 수만 개의 점도 빠르게 그리지만, 그려진 것은 그냥 픽셀이라 스크린 리더나 검색 엔진이 내용을 알 수 없다.

## 2. CSS와 브라우저 기본 기능으로 하는 애니메이션

라이브러리 없이도 할 수 있는 것이 많다. **먼저 CSS로 되는지 확인하자.**

### 2.1 transition과 animation

```css
.button {
  transition: transform 0.2s ease, background-color 0.2s;
}
.button:hover {
  transform: scale(1.05);
}

@keyframes fade-in {
  from { opacity: 0; transform: translateY(10px); }
  to   { opacity: 1; transform: translateY(0); }
}
.card {
  animation: fade-in 0.4s ease-out;
}
```

- **`transform`과 `opacity`만 애니메이션하는 것이 가장 부드럽다.** 레이아웃 계산 없이 GPU 합성 단계에서만 처리되기 때문이다.
- `width`, `top`, `margin` 같은 속성을 애니메이션하면 매 프레임 레이아웃을 다시 계산해서 버벅인다.
- cf. [Transition](/languages/css/04-Transition), [Animation](/languages/css/05-Animation), [Transform](/languages/css/06-Transform)

### 2.2 최신 브라우저 기능

| 기능                                  | 하는 일                                                                       |
| ------------------------------------- | ----------------------------------------------------------------------------- |
| **View Transitions API**              | 화면 A → B 전환을 브라우저가 부드럽게 연결 (같은 이미지가 확대되며 이동 등). 페이지 간(MPA) 전환도 지원 |
| **스크롤 기반 애니메이션**            | `animation-timeline: scroll()` / `view()`로 JS 없이 스크롤 진행도에 맞춰 애니메이션 |
| `@starting-style`                     | 요소가 처음 나타날 때(`display: none` → 표시)의 시작 스타일 지정              |
| `transition-behavior: allow-discrete` | `display`, `visibility`처럼 원래 애니메이션 안 되던 속성 전환                 |
| Web Animations API                    | `element.animate()`로 JS에서 CSS 애니메이션 제어                              |

```css
/* 스크롤할수록 진행 바가 차오른다 — JS 없음 */
.progress-bar {
  transform-origin: left;
  animation: grow linear;
  animation-timeline: scroll();
}
@keyframes grow {
  from { transform: scaleX(0); }
  to   { transform: scaleX(1); }
}
```

> 지원 브라우저는 [Baseline](https://web.dev/baseline)에서 확인하고, 지원하지 않는 브라우저에서는 애니메이션 없이도 내용이 보이도록 만들자. (점진적 향상)

## 3. 애니메이션 라이브러리

CSS만으로 어려운 경우 : 순서가 복잡한 타임라인, 드래그·제스처, 요소가 사라질 때의 애니메이션, 레이아웃이 바뀔 때 자연스럽게 이동, 물리 기반 움직임

| 라이브러리                                       | 특징                                                                            | 잘 맞는 것                      |
| ------------------------------------------------ | ------------------------------------------------------------------------------- | ------------------------------- |
| [Motion](https://motion.dev/) ✅ (구 Framer Motion) | React 애니메이션의 사실상 표준. 선언적 API, 퇴장(`AnimatePresence`)·레이아웃 애니메이션, 제스처 | React 앱의 UI 애니메이션        |
| [GSAP](https://gsap.com/) ✅                     | 정교한 타임라인, **ScrollTrigger**(스크롤 연동), SVG 모핑. 프레임워크와 무관. 현재 모든 플러그인 무료 | 브랜드·마케팅 사이트, 스크롤 연출 |
| [React Spring](https://www.react-spring.dev/)    | 스프링 물리 기반의 자연스러운 움직임                                            | 드래그, 탄성 있는 UI            |
| [Lenis](https://lenis.darkroom.engineering/)     | 부드러운 스크롤(smooth scroll)                                                  | 스크롤 연출 사이트              |
| [AutoAnimate](https://auto-animate.formkit.com/) | 한 줄로 목록 추가·삭제·정렬 애니메이션                                           | 간단한 목록                     |

```tsx
import { motion, AnimatePresence } from 'motion/react'

<AnimatePresence>
  {isOpen && (
    <motion.div
      initial={{ opacity: 0, y: 20 }}
      animate={{ opacity: 1, y: 0 }}
      exit={{ opacity: 0, y: 20 }} // 사라질 때도 애니메이션
    />
  )}
</AnimatePresence>
```

## 4. 3D 웹

### 4.1 Three.js

[Three.js](https://threejs.org/)는 WebGL(그리고 WebGPU)을 쉽게 쓰게 해 주는 **웹 3D의 표준 라이브러리** 다.
WebGL을 직접 쓰면 셰이더와 버퍼를 일일이 다뤄야 하지만, Three.js는 장면·카메라·물체 단위로 생각할 수 있게 해 준다.

3D 장면의 기본 구성

- `Scene` : 모든 물체를 담는 공간
- `Camera` : 어디서 어떻게 볼지 (원근감 있는 `PerspectiveCamera`가 기본)
- `Renderer` : 장면을 화면(canvas)에 그리는 엔진
- `Mesh` = `Geometry`(모양) + `Material`(재질·색)
- `Light` : 빛 (재질에 따라 빛이 없으면 검게 보인다)
- 애니메이션 루프 : 매 프레임 물체를 조금씩 움직이고 다시 렌더링

```js
import * as THREE from 'three'

const scene = new THREE.Scene()
const camera = new THREE.PerspectiveCamera(75, innerWidth / innerHeight, 0.1, 1000)
camera.position.z = 3

const renderer = new THREE.WebGLRenderer({ antialias: true })
renderer.setSize(innerWidth, innerHeight)
document.body.appendChild(renderer.domElement)

const cube = new THREE.Mesh(
  new THREE.BoxGeometry(1, 1, 1),
  new THREE.MeshStandardMaterial({ color: 'royalblue' }),
)
scene.add(cube)
scene.add(new THREE.DirectionalLight('white', 3))

renderer.setAnimationLoop(() => {
  cube.rotation.x += 0.01
  cube.rotation.y += 0.01
  renderer.render(scene, camera)
})
```

- 3D 모델은 주로 **glTF(`.glb`)** 형식을 쓴다. Blender 등에서 만든 모델을 `GLTFLoader`로 불러온다.
- 모델 용량을 줄이려면 Draco·Meshopt 압축, 텍스처는 KTX2 압축을 쓴다.

### 4.2 React Three Fiber

[React Three Fiber(R3F)](https://r3f.docs.pmnd.rs/)는 Three.js를 **React 컴포넌트로** 쓰게 해 주는 라이브러리다. (Zustand, Jotai를 만든 pmndrs 그룹 제작)

```tsx
import { Canvas, useFrame } from '@react-three/fiber'
import { OrbitControls } from '@react-three/drei'
import { useRef } from 'react'
import type { Mesh } from 'three'

function Box() {
  const ref = useRef<Mesh>(null)
  useFrame((_, delta) => {
    if (ref.current) ref.current.rotation.y += delta // 매 프레임 회전
  })
  return (
    <mesh ref={ref}>
      <boxGeometry />
      <meshStandardMaterial color="royalblue" />
    </mesh>
  )
}

export default function Scene() {
  return (
    <Canvas camera={{ position: [0, 0, 3] }}>
      <directionalLight intensity={3} />
      <Box />
      <OrbitControls /> {/* 마우스로 회전·확대 */}
    </Canvas>
  )
}
```

R3F 생태계

- **drei** : 카메라 컨트롤, 텍스트, 환경맵, 모델 로딩 등 자주 쓰는 도우미 모음
- **react-three-rapier** : 물리 엔진(충돌, 중력)
- **postprocessing** : 블룸, 피사계 심도 같은 후처리 효과
- **gltfjsx** : glTF 모델을 R3F 컴포넌트 코드로 변환

### 4.4 셰이더와 WebGPU

- **셰이더(Shader)** : GPU에서 실행되는 작은 프로그램. 픽셀 하나하나의 색(fragment shader)이나 정점 위치(vertex shader)를 계산한다.
  - 물결, 노이즈, 그라데이션, 왜곡 같은 독특한 효과는 대부분 셰이더로 만든다.
  - WebGL은 **GLSL**, WebGPU는 **WGSL** 언어를 쓴다.
  - Three.js의 **TSL(Three Shading Language)** 을 쓰면 JS로 셰이더를 작성해 WebGL·WebGPU 양쪽에서 쓸 수 있다.
  - 입문 자료 : [The Book of Shaders](https://thebookofshaders.com/?lan=kr)
- **WebGPU** : WebGL의 후속 표준. 최신 GPU 구조에 맞게 설계되어 더 많은 물체를 더 빠르게 그리고, **GPU로 일반 계산(compute)** 도 할 수 있다.
  - 현재 주요 브라우저 대부분이 지원을 시작했고, Three.js도 `WebGPURenderer`를 제공한다.
  - 브라우저에서 AI 모델을 실행하는 라이브러리(e.g. Transformers.js, WebLLM)도 WebGPU를 활용한다.

## 5. 인터랙티브 웹을 만들 때 주의할 점

### 5.1 성능

- 목표는 **초당 60프레임(한 프레임 약 16ms)**. 매 프레임 할 일이 이 시간을 넘으면 버벅인다.
- 애니메이션은 `transform`, `opacity` 위주로, JS 애니메이션은 `requestAnimationFrame` 사용 (라이브러리는 내부적으로 처리)
- 스크롤 이벤트에서 무거운 작업 금지 → Intersection Observer, CSS 스크롤 애니메이션 활용
- 3D
  - 모델·텍스처 용량 줄이기 (압축, 해상도 조절)
  - 화면에 보이지 않을 때는 렌더링 멈추기, 필요할 때만 렌더링(R3F `frameloop="demand"`)
  - `devicePixelRatio`를 상한(e.g. 2)으로 제한 → 고해상도 모바일에서 과도한 렌더링 방지
  - 같은 물체가 많으면 `InstancedMesh`로 한 번에 그리기
- **3D·애니메이션 라이브러리는 무겁다.** 필요한 페이지에서만 `dynamic import`로 지연 로딩하자. 첫 화면 성능(LCP)을 해치지 않도록.
- 저사양 기기·모바일에서도 꼭 테스트하자.

### 5.2 접근성

- **`prefers-reduced-motion`** : 사용자가 OS에서 "동작 줄이기"를 켰다면 애니메이션을 줄이거나 끈다. (어지럼증, 전정 장애가 있는 사용자 배려)

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.01ms !important;
    transition-duration: 0.01ms !important;
    scroll-behavior: auto !important;
  }
}
```

- Motion은 `useReducedMotion()`, GSAP은 `gsap.matchMedia()`로 같은 처리를 할 수 있다.
- 깜빡임은 초당 3회를 넘지 않게 한다. (광과민성 발작 위험)
- Canvas·3D 안의 정보는 스크린 리더가 읽지 못하므로, **중요한 내용은 HTML 텍스트로도 제공** 한다.
- 스크롤을 가로채거나(scroll hijacking) 사용자가 멈출 수 없는 자동 재생 애니메이션은 피한다.

### 5.3 SSR과 함께 쓰기

- Three.js, Canvas, `window`를 쓰는 코드는 **브라우저에서만** 실행된다.
- Next.js에서는 `'use client'` 컴포넌트로 만들고, 필요하면 `dynamic(() => import('./Scene'), { ssr: false })`로 서버 렌더링에서 제외한다.

## 6. 학습 순서 추천

1. **CSS 애니메이션** : `transition`, `@keyframes`, `transform` → 렌더링 파이프라인 이해
2. **Motion 또는 GSAP** : 실무 UI 애니메이션과 스크롤 연출
3. **Canvas 2D** : 좌표계, 애니메이션 루프, 간단한 파티클
4. **Three.js 기초** : 장면·카메라·조명·재질, glTF 모델 불러오기
5. **React Three Fiber + drei** : React 프로젝트에 3D 통합
6. **셰이더(GLSL/TSL)** 와 **WebGPU** : 독창적인 시각 효과, 고성능 그래픽

> 영감을 얻으려면 [Awwwards](https://www.awwwards.com/), [Codrops](https://tympanus.net/codrops/) 같은 사이트에서 인터랙티브 웹 사례를 많이 보자.
